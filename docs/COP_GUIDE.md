# 동국 규정 MCP — 구성원 시작 가이드

교원·직원·학생이 공개된 동국대학교 규정의 원문과 개정 이력을 찾아 업무를 검토하는 도구입니다. CoP에서는 같은 질문을 다른 구성원도 재현할 수 있도록 **질문 조건 → 근거 확인 → 검토 기록**을 함께 연습합니다.

이 문서는 v0.10.0 배포용 가이드입니다. 학교의 공식 해석이나 전 구성원 계정 개통을 의미하지 않습니다. 실제 사용 앱별 연결·권한과 현업 효과는 해당 환경에서 확인해야 합니다.

## 1. 사용할 경로 고르기

| 경로 | 준비 | 적합한 상황 |
|---|---|---|
| 내 PC에 설치 | Node.js 20.19 이상과 로컬 MCP를 지원하는 AI 앱 | 공유 인증정보 없이 공개 규정 조회를 시작할 때 |
| 운영자가 제공하는 공용 연결 | 원격 MCP를 지원하는 AI 앱, `/mcp/rules` 주소, 개인 또는 그룹에 배정된 인증정보 | 관리자가 서버 업데이트를 맡는 공동 이용 |

내 PC의 기본 `rules` 프로필은 공개 규정 도구만 제공합니다. Finance AI Desk의 지식팩·국가 법령 연계는 관리자가 별도로 구성하는 `finance` 프로필입니다. 규정 MCP 설치만으로 내부 재무자료나 다른 시스템에 대한 접근권한이 생기지는 않습니다.

공용 연결에는 기존 운영자가 안내한 주소를 사용합니다. 하나의 관리자 토큰을 전교에 공유하지 않습니다. 인증정보는 공개 게시물·설치 화면 캡처·질문 본문에 넣지 않습니다.

## 2. 내 PC에서 시작하기

명령은 macOS 터미널 또는 Windows PowerShell에서 실행합니다. `node --version`으로 20.19 이상인지 먼저 확인합니다.

```bash
npm install -g https://github.com/buenosiempre-cmd/dongguk-rule-mcp/releases/download/v0.10.0/dongguk-rule-mcp-0.10.0.tgz
dongguk-rule-mcp --version
dongguk-rule-mcp --doctor --json
```

첫 설치에는 패키지를 내려받기 위한 네트워크가 필요합니다. npm 레지스트리는 현재 미발행이므로 위 GitHub 릴리스 패키지를 사용합니다. 기관 PC의 설치 정책·방화벽 때문에 실행할 수 없다면 공용 연결 경로를 담당 운영자에게 요청합니다.

사용할 앱의 설정 예시를 출력합니다. 아래 세 명령 중 하나를 선택합니다.

```bash
dongguk-rule-mcp --print-config codex
dongguk-rule-mcp --print-config claude
dongguk-rule-mcp --print-config cursor
```

출력된 설정을 해당 앱의 MCP 설정에 **기존 연결을 보존하며 추가**하고 앱을 완전히 종료한 뒤 다시 실행합니다. 설정 출력은 예시를 만드는 기능이며 앱 설정을 직접 변경하지 않습니다. 앱의 요금제·관리자 정책·버전에 따라 연결 지원과 설정 위치가 다릅니다. 설치 명령 성공만으로 앱 연결 성공을 판정하지 않습니다.

글로벌 설치 권한이 없다면, 쓰기 가능한 작업 폴더에서 아래처럼 별도 하위 폴더에 설치할 수 있습니다. 설정 출력의 `codex`는 `claude` 또는 `cursor`로 바꿔도 됩니다.

```bash
npm install --prefix ./dongguk-rule-client https://github.com/buenosiempre-cmd/dongguk-rule-mcp/releases/download/v0.10.0/dongguk-rule-mcp-0.10.0.tgz
node ./dongguk-rule-client/node_modules/dongguk-rule-mcp/src/index.js --doctor --json
node ./dongguk-rule-client/node_modules/dongguk-rule-mcp/src/index.js --print-config codex
```

설정에 출력된 설치 폴더를 유지하세요. 폴더를 옮기거나 삭제하면 연결 경로가 바뀌므로 새 경로에서 설정을 다시 출력해야 합니다.

연결한 AI에게 아래처럼 요청합니다.

> 동국 규정 MCP의 `get_service_info`를 호출해서 버전과 사용 가능한 프로필·도구를 보여줘. 이어서 `lookup_dongguk_rule`로 공개 여비규정을 찾아 원문 링크와 개정본 식별자를 알려줘.

성공 조건은 **서버 버전 확인 + 도구 호출 성공 + 실제 규정 원문 링크 확인**입니다. `--doctor` 진단이나 서버 상태 응답만으로 규정 조회까지 성공했다고 보지 않습니다.

## 3. 질문할 때 알려줄 네 가지

1. **업무와 원하는 결과:** 원문 찾기, 기안문 인용 점검, 과거 기준 확인, 개정 비교 중 무엇인지 적습니다.
2. **적용 조직:** 서울·WISE·법인·소속 대학원 등 실제 소속과 관련 조직을 적습니다.
3. **대상:** 교원·직원·강사·학생 등 해당 신분과 필요한 자격 조건을 적습니다.
4. **기준일:** 사건 발생일·출장일·임용일 등 규정 적용을 검토할 날짜를 적습니다.

알 수 없는 조건은 추측해서 채우지 말고 “미확인”이라고 적습니다. 이름·학번·주민등록번호·계좌번호·개인별 급여·학생기록을 넣지 않아도 규정 탐색을 시작할 수 있습니다.

### 복사해서 쓰는 기본 질문

```text
동국 규정 MCP로 다음 사안의 근거를 찾아줘.
- 업무/질문: [규정 검색 또는 확인할 내용]
- 조직/캠퍼스: [서울/WISE/법인/기타, 미확인이면 미확인]
- 대상 신분: [교원/직원/강사/학생/기타]
- 기준일: [YYYY-MM-DD]

확인 가능한 내용, 먼저 확인할 사실, 규정명·개정본·조문/별표·원문 링크,
다음 검토 순서와 확인되지 않은 부분으로 답해줘.
최신 개정본이 이 사안에 적용된다고 가정하지 말고 시행일·경과조치를 확인해줘.
표에 근거한 금액이나 전결권자는 해당 행·열·단위·직군을 확인하기 전 확정하지 마.
```

## 4. 구성원별 첫 실습

아래는 학습용 질문입니다. 각 대상에게 특정 규정이 실제 적용된다고 미리 정한 예시는 아닙니다.

| 대상 | 질문 예시 | 반드시 확인할 것 |
|---|---|---|
| 서울 직원 | “기준일 [날짜]의 국내출장 여비 관련 규정을 찾아줘.” | 소속·직군·여비 별표의 행/열·단위·시행일 |
| WISE 직원 | “WISE 소속 직원의 출장에 적용할 규정 후보를 찾고 적용범위 근거를 보여줘.” | 규정 본문에 적힌 캠퍼스·조직 적용범위 |
| 교원·강사 | “소속과 임용 구분에 맞는 복무 관련 규정 후보를 찾고 추가로 확인할 사실을 정리해줘.” | 임용 구분·직군·규정 사이 관계 |
| 학사 담당자·학생 | “소속 과정의 휴학 관련 규정을 찾아줘. 학부와 대학원 기준을 구분해줘.” | 학적·과정·대학원 구분·기준일, 세부 학사 지침 여부 |
| 연구·행정 담당자 | “이 비식별 기안문에 적힌 규정 인용이 실제 존재하는지 확인해줘.” | 인용 실존과 업무 적용 적합성을 각각 검토 |
| 대체 담당자 | “이 근거 기록을 보고 같은 개정본·조문·별표를 다시 찾아줘.” | 원문 링크·LAW_ID·HISTORY_ID·조회일의 재현 |

이 버전은 캠퍼스별 자동 필터를 제공하지 않습니다. `campus` 입력은 업무 맥락으로 보존하고 전체 통합목록에서 검색합니다. 결과의 정확한 규정명·LAW_ID를 선택한 뒤 원문에서 적용범위를 확인합니다. 서울에서 쓰던 답을 WISE에 재사용하거나, 직원의 기준을 교원·학생에게 적용할 때는 원문을 다시 확인합니다. 규정 사이트가 제공하지 않는 내부 지침·협약·개별 처분까지 조회된 것으로 보지 않습니다.

운영 확인 근거: 2026-09-08 [공식 검색 화면](https://rule.dongguk.edu/lmxsrv/main/main.srv)의 `LAWGROUP` 값은 캠퍼스 구분이 아니며, [통합 규정목록](https://rule.dongguk.edu/lmxsrv/law/lawTree.srv)에서 제목과 조직별 원문을 확인해야 합니다.

## 5. 답변을 업무에 쓰기 전 확인

| 확인 항목 | 기록할 내용 |
|---|---|
| 근거 | 규정명, 원문 URL, LAW_ID, HISTORY_ID, 조문 또는 별표 위치 |
| 시점 | 업무 기준일, 개정일, 확인한 시행일·경과조치, 조회일 |
| 범위 | 캠퍼스·조직·직군·대상 조건을 확인한 문구 |
| 표 | 표 제목, 대상 행, 항목 열, 금액/단위와 주석 |
| 완전성 | 발췌 잘림·HTML 대체·HWP 실패·검색어 미일치 여부 |
| 검토 | 작성자 이외 검토 여부, 미해결 질문, 담당 부서 확인 필요 사항 |

`verify_rule_citations`의 확인 결과는 인용의 실존 점검입니다. 해당 사안의 최종 해석이나 적용 적합성을 보장하지 않습니다. `applicable_rule`의 기준일 결과도 개정 이력을 바탕으로 한 후보이므로 부칙을 함께 봅니다. `compare_rule_versions`는 기본적으로 HTML 조문과 HWP 별표·서식의 추출 텍스트를 각각 비교합니다. 표의 의미·병합 셀·그림·첨부파일까지 완전히 검증하지는 않으며, 금액·전결권의 실제 변화와 적용은 원문에서 확인해야 합니다. 별표를 식별하지 못했거나 추출에 실패한 부분 상태를 “변경 없음”으로 해석하지 않습니다.

답변에 `partial`, `확인필요`, 원문 누락 또는 잘림이 표시되면 해당 항목을 검토 메모에 남깁니다. 검색 결과가 없으면 검색어를 짧게 바꾸고 정확한 규정명이나 원문 시스템을 확인합니다. 검색 0건을 “관련 규정 없음”으로 단정하지 않습니다.

## 6. CoP 20분 실습

1. **0–5분:** 연결 확인, `get_service_info`, 공개 규정 검색을 실행합니다.
2. **5–10분:** 조직·직군·기준일 중 하나를 비운 질문과 채운 질문을 비교합니다.
3. **10–15분:** 원문과 개정본을 열고 조문·별표를 확인해 근거 기록을 작성합니다.
4. **15–20분:** 다른 구성원이 같은 기록으로 조회를 재현하고 오류·누락을 적습니다.

진행자는 설치 완료 인원, 원문 조회 성공 인원, 조건 누락을 발견한 인원, 재현 성공 인원을 구분해서 기록합니다. 시간절감이나 정확성 향상은 [실증평가 가이드](EVALUATION.md)로 별도 측정합니다.

## 7. 도움이 필요할 때

- 도구가 보이지 않으면 앱 재시작, 설정 문법, Node 버전, 실행 경로를 확인합니다.
- 인증 실패는 공용 서버 운영자에게, 원문 접속 실패는 발생 시각과 오류코드를 운영자에게 알립니다.
- 잘못된 적용범위·금액·전결권·인용은 해당 업무 담당자에게 원문과 함께 확인합니다.
- 공개 소프트웨어 오류는 [GitHub Issues](https://github.com/buenosiempre-cmd/dongguk-rule-mcp/issues)에 버전·비식별 재현 질문·오류코드만 남깁니다. 내부 문서나 인증정보는 올리지 않습니다.

운영 담당자는 [운영 가이드](OPERATIONS.md)를 사용합니다. 이 배포에는 단체 메일·Slack 발송, 모든 구성원 계정 설치, 기관 SSO 또는 앱별 관리 정책 설정이 포함되어 있다고 가정하지 않습니다.
