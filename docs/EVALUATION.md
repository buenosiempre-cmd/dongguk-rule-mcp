# 동국 규정 MCP — CoP 실증평가 가이드

이 문서는 현업 검증을 실행하기 위한 설계입니다. 아래 수치들은 **미측정 목표**이며 v0.9.0의 자동 테스트 통과율, 법률 정답률 또는 전교 이용 효과가 아닙니다.

## 1. 확인할 질문

1. 구성원이 자기 앱에서 연결하고 공개 규정 원문을 찾을 수 있는가?
2. 캠퍼스·직군·기준일을 구분하고 조문·별표를 올바르게 확인하는가?
3. 원문 누락·입력 부족·시점 차이가 있을 때 필요한 확인을 남기는가?
4. 작성자가 없어도 다른 구성원이 같은 근거를 찾아 검토를 이어갈 수 있는가?
5. 기존 방식보다 검토 가능한 답변을 준비하는 시간이 줄어드는가?

## 2. 설치 확인과 현업 평가를 나누기

| 단계 | 관찰할 것 | 성공 증거 |
|---|---|---|
| 연결 | 설치, 앱 설정, 서버 버전·프로필 | `get_service_info`, 실제 도구 목록 |
| 원문 조회 | 공개 검색과 HWP/HTML 원문 | 규정명·개정본·원문 링크, 추출 경고 |
| 업무 적용 | 조건·시점·범위·표·다음 검토 | 검토자 점수와 오류 기록 |
| 재사용 | 작성자 외 사용자의 재현 | 도움 없이 같은 근거를 찾은 기록 |
| 확산 | 부서·캠퍼스·직군별 반복 검증 | 실제 참여 범위, 실패와 추가 요구 |

정상 상태 응답만으로 원문 조회 성공을, 자동 회귀 통과만으로 현업 효과를 판정하지 않습니다. 앱·캠퍼스·직군별 검증을 수행하지 않았으면 결과표에 “미검증”으로 남깁니다.

## 3. 소규모 파일럿 설계

- 참가자 5명을 P01~P05로 기록합니다. 명단과 개인 연락처는 이 저장소에 넣지 않습니다.
- 세 가지 시나리오에 대해 난이도가 비슷한 A/B 문제를 준비합니다.
- 참가자마다 기존 방식과 MCP 보조 방식의 순서를 교차 배치합니다. 같은 문제의 답을 외워 빨라지는 효과를 줄이기 위해 동등한 다른 문제를 사용합니다.
- 1명이 3개 시나리오를 두 방식으로 수행하여 **15쌍, 30회 관찰**을 수집합니다. 참가자 수는 5명이며 30명의 독립 표본으로 보고하지 않습니다.
- 검토자 2명이 각 결과를 독립 채점합니다. 합의 전의 점수와 이견을 보존합니다.

다음 세 시나리오는 공통 공개 규정 조회의 시작 예시입니다. 파일럿 담당자가 원문에서 정답 근거를 검토한 뒤 확정합니다.

| 시나리오 | 과제 | A/B 문제를 만들 때 |
|---|---|---|
| S01 적용범위·표 확인 | 출장 관련 규정 후보, 직군/캠퍼스 적용 문구와 별표 위치를 찾기 | 유사 난이도의 대상·조건을 사용하고 표의 행·열·단위를 모두 요구 |
| S02 과거 기준·개정 확인 | 사건 기준일의 개정본 후보와 시행일·경과조치를 확인하기 | 기준일 전후 개정 상황을 포함하고 현행본과 구분 |
| S03 기안문 인용·인계 | 비식별 학습용 기안문 인용을 점검하고 다른 담당자가 재현할 근거 메모 만들기 | 잘못된 조문 번호 또는 불충분한 인용을 포함하되 실제 비공개 기안문은 사용하지 않음 |

정답에 특정 금액·전결권자가 포함되면 원문 표를 검토자가 먼저 확인합니다. 원문 불완전 또는 적용범위 미확정 문제는 “보류하고 확인할 사실을 제시”하는 것도 정답으로 설계합니다.

## 4. 확산 전 검증 범위

5인 파일럿만으로 다음 전체 집단의 사용성을 입증할 수 없습니다. 실제 확산 대상에서 대표 사용자를 추가하고 확인한 범위를 기록합니다.

| 축 | 확인할 구분 | 미확인 때 표시 |
|---|---|---|
| 소속 | 서울, WISE, 법인 또는 기타 관련 조직 | 해당 소속 미검증 |
| 대상 | 직원, 교원, 강사, 학부생, 대학원생 등 실제 이용 대상 | 해당 직군/과정 미검증 |
| 환경 | 실제 사용하는 AI 앱·운영체제·로컬/원격 접속 | 해당 환경 미검증 |
| 질문 | 최신 규정, 과거 시점, 조문 인용, 표, 검색 결과 없음 | 해당 흐름 미검증 |
| 장애 | 원문 오류, 표 누락, 잘림, 인증 실패, 요청 제한 | 해당 오류 처리 미검증 |

모든 조합을 무조건 전수 검사하기보다 사용량·적용 오류 위험이 큰 조합을 먼저 고릅니다. 캠퍼스/직군을 잘못 적용하거나 민감정보가 노출된 사례는 그 흐름을 수정하고 재검증한 후 범위를 넓힙니다.

## 5. 채점 기준

각 항목을 0점(없음/오류), 1점(부분), 2점(충족)으로 채점합니다. 해당하지 않는 항목은 N/A로 기록하고 합산 분모에서 제외합니다.

| 항목 | 2점 기준 |
|---|---|
| 조건 확인 | 결론을 바꾸는 캠퍼스·조직·직군·기준일을 확인하거나 미확인으로 명시 |
| 근거 추적 | 규정명·LAW_ID·HISTORY_ID·조문/별표·원문 링크·조회일을 재현 가능하게 기록 |
| 시점·범위 | 개정일과 시행일·경과조치를 구분하고 실제 대상의 적용범위를 확인 |
| 표·내용 | 표의 행·열·단위 또는 관련 조문을 원문과 대조, 누락/잘림을 숨기지 않음 |
| 불확실성 | 입력 부족·검색 0건·원문 실패·해석 충돌 시 단정하지 않고 확인 사항 제시 |
| 다음 검토·인계 | 다른 담당자가 수행할 다음 단계와 남은 질문을 기록 |

중대 오류는 점수 합계와 별도로 집계합니다. 예: 틀린 캠퍼스·직군·시행일 적용, 확인하지 않은 금액·전결권 확정, 존재하지 않는 규정의 확정 인용, 조회만으로 신고·지급·결재 완료라고 답변, 민감정보 노출.

## 6. 수집 양식과 측정

[cop-evaluation.csv](../examples/cop-evaluation.csv)는 30회의 예정 관찰 행을 둔 **빈 측정 양식**입니다. 참가자 ID·시나리오·짝·방식·예정 순서만 들어 있으며 시간·점수·결과는 비어 있습니다. 원문 파일이나 개인 정보를 CSV에 붙여 넣지 않습니다.

- `method`: `manual`은 기존 방식, `mcp`는 MCP 보조 방식입니다.
- `form`: 동급 난이도의 `A` 또는 `B` 문제입니다. 진행 전 검토자가 문제와 근거를 확정합니다.
- `planned_order`: 같은 쌍 안에서 1·2 순서입니다. 실제 순서가 달라졌으면 기록을 정정합니다.
- `elapsed_seconds`: 문제 확인부터 검토 가능한 산출물 제출까지의 시간입니다. 실패·중단도 남깁니다.
- `correction_seconds`: 제출 뒤 검토 결과에 따른 수정 시간입니다. 총시간은 두 시간을 합산합니다.
- `completed_without_help`: 도움 없이 완수하면 `yes`, 도움을 받거나 미완수면 `no`입니다.
- `scope_verified`, `table_verified`: 원문 확인 결과를 `yes`/`no`로 기록하고 해당 항목이 없으면 `not_applicable`로 적습니다. 미검토 값은 비워 둡니다.
- `reviewer1_score`, `reviewer2_score`, `agreed_score`: 적용 항목 합산 점수와 최대 점수를 `10/12`처럼 기록합니다. 상세 항목별 점수는 접근제한 평가 기록에 보관합니다.
- `critical_error_count`: 중대 오류 수입니다. 미검토를 0으로 채우지 않습니다.
- `result_status`: `completed`, `partial`, `failed`, `not_run` 중 실제 상태를 적습니다. 빈 값은 미측정입니다.
- `notes_redacted`: 실패·기준 변경·도움 여부를 비식별로 기록합니다.

시간절감률은 같은 `pair_id`의 두 관찰에서 다음처럼 계산합니다.

```text
기존 총시간 = manual.elapsed_seconds + manual.correction_seconds
MCP 총시간 = mcp.elapsed_seconds + mcp.correction_seconds
절감률(%) = (기존 총시간 - MCP 총시간) / 기존 총시간 × 100
```

기존 시간이 0이거나 어느 한쪽이 미측정이면 절감률을 계산하지 않습니다. 실패한 관찰을 삭제하거나 시간을 0으로 치환하지 않습니다. 완료율을 따로 보고하고, 양쪽 완료 쌍에 대한 시간 분석에는 제외된 실패·중단 건수와 이유를 함께 적습니다.

| 지표 | 초안 목표 — 미측정 | 보고 방식 |
|---|---|---|
| 답변 준비·수정 총시간 | 쌍별 절감률 중앙값 30% 이상 | 중앙값·범위·유효 쌍 수·실패/중단 수 |
| 중대 오류 | 0건 | 유형·발생 조건·수정·재검증 결과 |
| 대체 담당자 완수 | 80% 이상 | 완수 수/해당 과제 수, 도움 여부 |
| 근거 추적 | 평가 대상 규범적 주장 100% | 누락한 링크·버전·조문/별표 기록 |
| 불확실성 처리 | 해당 평가 사례 100% | 누락 사실·원문 불완전 시 허용 결론 준수 |

표본이 작으므로 학교 전체의 시간절감률이나 통계적 유의성을 과장하지 않습니다. 자동 회귀 검사 결과와 사람의 현업 점수는 서로 다른 표로 보고합니다.

## 7. 공유할 결과물

공개 공유본에는 검증한 범위, 버전, 비식별 질문, 근거 링크, 집계 결과, 실패 유형, 개선 전후 사례를 넣습니다. 참여자 명단·내부 원문·인증정보·개인별 업무 기록은 포함하지 않습니다.

CoP 결과에는 다음을 구분합니다.

- 구현·배포·원문 연결을 검증한 결과.
- 실제 참여자 수와 앱·캠퍼스·직군 범위.
- 측정한 효과와 미측정 목표.
- 실패·수정·재검증 결과, 추가 확산에 필요한 조건.

질문 주제 세 가지를 제공한 것만으로 기관 KPI의 “AI 적용 3건” 달성을 확정하지 않습니다. 실제 업무 사용·산출물·효과와 기관의 인정 기준을 별도로 확인합니다.
