# Finance Desk 사용과 운영

v0.10.0 확장 작업의 안내입니다. Finance Desk는 교내 규정·법령·특례규칙 해설·실무 매뉴얼을 함께 조회하고 검토 근거를 모읍니다. 배포·실사용 확인 결과는 해당 릴리스 기록과 구분합니다.

## 평소 업무처럼 질문하세요

- “이 기안문이 동국대 규정에 맞는지 검토해줘.”
- “이거 무슨 계정으로 처리해?”
- “어떤 증빙이 필요해?”

문서가 있으면 첨부하거나 검토할 문장을 선택하면 됩니다. 사용자가 도구명·규정 식별번호·긴 입력 양식을 준비할 필요는 없습니다. AI는 대화에서 확인한 조건을 사용하고, 회계단위·거래일·지급 경로 등에 따라 판단이 달라질 때 필요한 사항을 질문해야 합니다.

답변은 검토 의견, 주장별 근거 위치, 계정·증빙·절차 후보, 수정안과 추가 확인 사항을 함께 제시합니다. 법령 조회 성공과 실제 사안의 적정 판정은 구분합니다.

## 연결 구조와 자료의 역할

| 자료 | 연결 | 답변에서의 역할 |
|---|---|---|
| 동국대 규정·별표·연혁 | 동국 규정 MCP | 교내 적용범위와 기관 기준 확인 |
| 법령·특례규칙·별표 | KoreanLaw MCP | 법령 원문과 거래 시점 확인 |
| 특례규칙 해설서 | 별도 외부 해설팩 | 계정·개념·사례 설명과 원문 위치 제공 |
| 실무 매뉴얼 | 별도 외부 실무팩 | 증빙 탭·접수·내역 연결의 참고 후보 |

해설·FAQ·실무 매뉴얼을 법령과 같은 효력의 자료로 취급하지 않습니다. 교비·법인 일반업무와 병원·수익사업·산학협력단의 회계체계도 구분해야 합니다. 자료의 판본·시행일·조회일·출처 위치를 남기고 충돌과 누락을 표시합니다.

## 공개 규정과 내부 Finance Desk 분리

기본 `rules` 프로필과 인증된 `/mcp/rules` 경로는 공개 규정 **10개 도구**만 제공합니다. 해설서·실무팩·재무 검토 도구를 이 경로에 노출하지 않습니다.

선택한 `finance` 프로필은 기존 재무 도구에 `search_finance_handbook`과 `review_finance_case`를 추가하는 확장 범위입니다. 후자는 짧은 업무 질문의 기본 조회 창구이며, 필요한 교내 규정·법령·해설·실무 후보를 함께 모읍니다. 기존 출장·강사료·소득 정정 흐름은 기존 재무 도구와 함께 사용합니다.

공유할 때는 내부 자료를 볼 수 있는 이용자와 인증 경로를 별도로 정합니다. 공개 규정 연결을 설치했다는 이유로 내부 Finance Desk 접근권한이 생기는 것은 아닙니다. 기관 SSO나 모든 구성원의 계정 설정은 별도 운영 사항입니다.

## 운영자가 연결할 외부 자료

공개 GitHub 저장소와 npm 패키지에는 코드·빌더·합성 테스트만 넣습니다. **내부 지식팩, 매뉴얼 원문, 인증키는 포함하지 않습니다.** 기존 운영 설정·법령 연결·인증 등록 파일은 보존하고 검증한 버전별 실행 폴더를 전환합니다.

| 설정 이름 | 지정할 외부 파일 |
|---|---|
| `DONGGUK_FINANCE_PACK_PATH` | 기존 재무 업무 카드와 흐름 |
| `DONGGUK_HANDBOOK_PACK_PATH` | 출처·판본·원문 위치를 포함한 해설팩 |
| `DONGGUK_PRACTICE_PACK_PATH` | 출처·원문 줄·해시를 포함한 실무팩 |

법령 연결은 기존 KoreanLaw 실행 설정을 사용합니다. 비밀값을 명령행·문서·로그에 적지 않습니다. 진단에서 연결이 미구성으로 나오면 실제 자료 연결과 별도로 기록합니다.

실무팩 빌더는 검토한 두 매뉴얼 파일을 명시적으로 받아 저장소 밖의 새 파일을 생성합니다. 출력은 권한 `0600`이며 기존 파일을 덮어쓰지 않습니다.

```bash
node scripts/build-practice-pack.js \
  --evidence-file /secure/manuals/evidence.md \
  --voucher-file /secure/manuals/voucher.md \
  --out /secure/finance/practice-pack.json
```

예시 경로를 실제 접근제한 경로로 바꿉니다. 자료를 공개 저장소 밖에 두는 것과 적법한 이용·공유 범위를 확인하는 일은 운영자가 함께 관리합니다.

## 현재 확인 범위

- v0.9.0에서 가상 강의료 사례의 교내 규정·법령 동시 조회를 확인했습니다. 실제 지급 판단은 추가 검토 상태였습니다.
- 실무 모듈은 일반 비용·학교 직접 지급·미지급/지급 전·서울 조건에서 세금계산서·법인카드·현금영수증 참고 후보를 선택합니다. 조건이 부족하면 조건부 후보와 확인 질문을 반환하고, 환입·자산·개인 지급·e나라도움·다른 캠퍼스 등은 적용하지 않습니다.
- 실무 후보는 항상 `manual_reference_unverified_current_ui`입니다. 정확한 Markdown 줄과 해시를 남기지만 현재 nDRIMS 화면·저장·결재·지급을 검증하거나 실행하지 않습니다. 원본 HWP 해시는 메타데이터 기록값이며 원본 파일 재검증으로 표시하지 않습니다.
- 증빙 내역 연결과 별도 파일 첨부를 구분합니다. 선택한 매뉴얼만으로 첨부 종류·필요 여부를 확정하지 않습니다.
- 해설서 변환본의 표·분개·차변·대변·금액은 원문 표 대조가 필요한 경우를 표시합니다. 검색 결과를 완전한 표나 확정 계정으로 간주하지 않습니다.
- 합성 테스트, 실제 자료팩 구성, 실제 앱 호출, 구성원별 사용과 업무 효과는 각각의 결과로 기록합니다. 전체 구성원 보급·전교 동시접속·현재 업무화면·업무 효과는 별도 검증 대상입니다.

실무 모듈의 독립 검증 명령은 `node test/test-practice.js`입니다. 통합 테스트와 실제 배포 검수는 [운영 가이드](OPERATIONS.md), CoP 평가는 [평가 설계](EVALUATION.md)를 참고하세요.
