# 동국 규정 MCP — 공동 이용 운영 가이드

대상 버전: v0.15.10. 기본 배포는 공개 규정 조회용 `rules` 프로필입니다. 이 문서는 운영자가 반복할 절차이며, 기관 승인·담당자 배정·전교 사용자 실증·가용성 SLA의 완료 증빙은 아닙니다.

## 1. 프로필과 접속 경계

| 구성 | 목적 | 운영 기준 |
|---|---|---|
| `rules` — 기본값 | 공개 교내 규정 조회 | 내부 재무지식팩과 로그인 쿠키를 사용하지 않는 일반 구성원 배포 |
| `finance` — 선택 | 공개 규정·한국법령 공동 조회 및 별도 구성한 내부 자료팩 | `--profile finance` 또는 `DONGGUK_MCP_PROFILE=finance`, 승인된 이용 범위 내 운영 |
| `POST /mcp/rules` | 공개 규정 도구 전용 공용 경로 | 서버가 `finance`여도 규정 전용 경로. 공용 서버에서는 인증 없이 열고 IP별 호출 제한 적용 |
| `POST /mcp` | 해당 서버 프로필의 MCP 경로 | 기존 연결 호환, 운영자가 설정한 프로필과 접근권한 확인 |

일반 구성원에게는 로컬 `rules` 설치 또는 공용 `/mcp/rules` 주소를 안내합니다. `finance` 프로필 활성화, 내부 지식팩 배포, 로그인 쿠키 사용은 각각 독립적으로 관리합니다. 기존 Finance AI Desk 연결이 있다면 프로필 변경 전 도구와 권한의 영향을 확인합니다.

2026-11-11부터 공용 서버의 `/mcp/rules`는 인증 없이 공개합니다. 공개 대상은 로그인 쿠키와 내부 자료팩을 쓰지 않는 읽기 전용 규정 도구뿐이며, [호출 제한](#공개-엔드포인트-호출-제한)으로 남용을 막습니다. 재무 기능이 있는 `/mcp`는 토큰 인증을 유지하고, 관리자 인증정보 하나를 전 구성원에게 나누어 주지 않습니다. 기관 SSO·이용자 명부 연계·자동 계정 회수는 별도 인프라와 운영 절차가 필요한 항목입니다.

| 공개 주소(2026-11-11 확인) | 인증 | 범위 |
|---|---|---|
| `https://dgu.kr-univ-rules.com/mcp/rules` | 없음, IP별 호출 제한 | 공개 규정 도구 |
| `https://dgu.kr-univ-rules.com/mcp` | Bearer 토큰 | 규정 + 재무 기능 |
| `https://dgu-slack.kr-univ-rules.com/mcp` | 없음, IP별 호출 제한 | Slackbot 연결용 공개 규정 도구 |

코드에서는 토큰을 설정한 프로세스의 모든 MCP 경로가 인증을 요구합니다. 따라서 인증 없는 주소는 토큰을 설정하지 않은 별도 `rules` 프로세스로 띄우고, 터널에서 주소별로 프로세스를 나눕니다. 토큰 없는 프로세스를 `finance` 프로필로 띄우지 않습니다.

## 2. 역할 지정

| 역할 | 책임 | 남길 기록 |
|---|---|---|
| 서비스 운영자 | 버전·배포·인증·장애·복구 | 배포/복구 시각, 버전, 진단 결과 |
| 규정·업무 검토자 | 적용범위·시점·표·해석 오류 검토 | 근거 위치, 판정, 미해결 사항 |
| CoP 진행자 | 실습·질문 수집·타 부서 재사용 | 비식별 질문, 교육 및 연결 성공 기록 |
| 평가 담당자 | 전후 비교와 실패 포함 측정 | 원점수, 시간, 오류, 조건 |

실명·연락처·인증정보는 공개 저장소가 아닌 기관의 운영 기록에 보관합니다. 담당자가 지정되지 않았으면 “운영책임자 미지정”으로 남기고, 이 문서가 자동으로 업무를 배정한 것으로 처리하지 않습니다.

## 3. 배포 전 확인

복구할 기존 패키지 버전과 설정의 위치를 기록하고, 비밀값이 포함된 설정은 접근제한 영역에 백업합니다. 소스 변경이 없는 배포라면 이미 통과한 같은 버전의 전체 테스트를 불필요하게 반복하지 않아도 되지만, 배포 대상 환경의 기동·인증·원문 조회는 확인합니다.

소스에서 릴리스를 검증할 때:

```bash
npm ci
npm test
npm run test:live
npm pack --dry-run
node src/index.js --version
node src/index.js --doctor --json
```

다음 내용을 배포 기록에 남깁니다.

- 태그·커밋·패키지 파일명·해시와 Node 버전.
- 오프라인 회귀 결과, 실원문 조회 결과, 미실행 또는 실패한 검사.
- `rules`에서 재무 도구가 노출되지 않는지와 `finance`의 선택 연결 상태.
- 공개 `/mcp/rules`가 인증 없이 규정 도구만 돌려주는지, `/mcp`의 인증 없는 요청 거절·올바른 인증의 호출 성공·폐기된 인증의 거절, 호출 제한 초과 시 429.
- 공개 패키지·로그·문서에 내부 지식팩, 쿠키, 인증값, 개인별 자료가 포함되지 않는지.

태그 고정 설치 예시:

```bash
npx -y https://github.com/buenosiempre-cmd/dongguk-rule-mcp/releases/download/v0.15.10/dongguk-rule-mcp-0.15.10.tgz --version
```

`latest`나 개발 브랜치가 자동으로 운영에 반영되도록 구성하기보다 검증한 릴리스 단위를 설치합니다. 기존 프로세스는 패키지 파일을 교체해도 구버전을 계속 사용할 수 있으므로 재시작 후 버전을 다시 확인합니다.

### 클라이언트와 기존 연결 갱신

파일 설치, 실행 중인 서버, 앱이 이미 연결한 MCP 프로세스는 서로 다른 상태입니다. 다음 세 버전을 별도로 기록합니다.

| 확인 지점 | 확인 방법 | 의미 |
|---|---|---|
| 설치 런타임 | 실제 런처가 가리키는 실행 파일의 `--version` | 다음 시작에 사용할 코드 |
| 공용 HTTP 서버 | `/health`, 이어서 인증된 `get_service_info` | 현재 요청을 받는 서버 |
| Codex·Aside 실제 연결 | 각 앱에서 `get_service_info` 호출 | 해당 앱의 현재 연결이 쓰는 코드 |

1. 새 버전은 별도 디렉터리에 설치하고 검증한 뒤 기존 런처의 대상 경로를 바꿉니다. 공개용과 내부용 런처, 쿠키·인증 헤더·자료팩·한국법령 연결은 기존 경계를 보존합니다.
2. 운영자 장비의 해당 MCP HTTP 서비스만 재시작합니다. 터널이나 다른 앱을 함께 재시작할 필요는 없습니다. 인증 거절·허용 경로·대표 원문 비교를 다시 확인합니다.
3. Codex의 기존 stdio 연결은 패키지 교체 후에도 구버전을 유지할 수 있습니다. 기존 연결을 확실히 갱신하려면 진행 중인 작업을 정리하고 Codex 앱을 완전히 종료한 뒤 다시 실행합니다. 앱 재시작은 실행 중인 대화를 중단할 수 있으므로 배포·검증을 끝낸 후 시행합니다. 재실행 후 실제 `get_service_info` 응답을 받기 전에는 “기존 연결 갱신 완료”로 기록하지 않습니다.
4. Aside는 실행 중인 데몬이 설정 파일을 덮어쓸 수 있으므로 `settings.json`을 직접 고치지 않습니다. `aside skills show aside`로 현재 공식 API를 확인하고, `aside repl --account u0`에서 `aside.settings.get('mcp')`로 읽은 설정을 보존한 채 `aside.settings.set('mcp', ...)`를 사용합니다. 새 런타임의 `tools/list`로 확인한 해당 서버의 `inventories`만 갱신하고 `refreshedAt`은 `Z`로 끝나는 UTC 시각으로 저장합니다. 기존 `servers`와 다른 도구 목록을 바꾸지 않았는지 재조회해 확인합니다. 실제 계정 ID는 운영 환경에 맞춥니다.
5. Aside 도구 목록 저장 성공은 도구 실행 성공과 다릅니다. Aside에서 `get_service_info`와 대표 비교를 호출해 버전·결과를 확인합니다. 연결이 구버전을 유지하면 해당 앱의 재연결 절차를 진행하고 다시 확인합니다.

### HWP 구조 비교와 캐시 전환

개발판 v0.12.1은 조문 소속이 추가된 `original-structure-v2` 캐시를 사용합니다. 이전 캐시를 삭제하지 않고 원문을 새로 조회하므로 30일 본문 캐시가 조문 범위 수정을 가리지 않습니다. 구조 데이터에 조문 소속이 없는 경우에는 해당 개체를 선택 조문 비교에서 제외하고 `STRUCTURE_ARTICLE_SCOPE_UNAVAILABLE` 및 `partial`을 표시합니다. `article`은 본문 구조에도 적용되며, `include_appendices:true`일 때 별표·서식 전체 비교는 독립적으로 수행합니다.

v0.12.0은 원문 캐시 이름을 `original-structure-v1`로 분리합니다. 이전 텍스트 전용 원문 캐시를 구조 분석 결과로 재사용하지 않으며, 첫 조회에서 HWP를 다시 받아 셀·병합 범위·그림 파일과 문서별 추출 진단을 저장합니다. 전체 캐시나 사용자 설정을 지울 필요는 없습니다. 이전 버전으로 롤백해도 새 구조 캐시를 이전 형식으로 읽지 않습니다.

대표 검증에는 HWP 조문 변경, 표의 값·행/열 병합 변경, 그림 파일 내용 변경, HWP 실패 시 HTML 부분 비교, 미지원 객체·추출 누락의 진단을 포함합니다. 그림 비교는 포함된 파일 바이트의 SHA-256 비교이며 OCR·의미 해석·페이지 배치 검증을 포함하지 않습니다. 결과와 실제 미지원 항목을 함께 보고하고, 한 문서의 성공을 모든 HWP 형식에 대한 보장으로 확대하지 않습니다.

## 4. 공용 서버 기동과 검수

원격 인증은 접근제한 서비스 환경파일 또는 비밀 관리 기능에서 주입합니다. 토큰을 명령행 인자·문서·쉘 기록에 직접 적지 않습니다. 공용 운영은 다중 자격증명 파일로 개인/그룹과 운영자 권한을 관리합니다. 기존 관리자 자격증명을 전 구성원 배포에 재사용하지 않습니다.

다중 자격증명 파일은 `--token-file /운영용/절대경로/tokens.json` 또는 `DONGGUK_MCP_TOKEN_FILE`로 지정합니다. JSON 최상위 `tokens` 배열의 각 항목에는 다음 속성을 둡니다.

| 속성 | 의미 |
|---|---|
| `id` | 개인 이름 대신 사용하는 관리용 ID |
| `sha256` | 발급 토큰의 SHA-256 해시, 64자리 16진수; 평문 토큰은 저장하지 않음 |
| `enabled` | `true` 사용, `false` 회수 |
| `expiresAt` | UTC 만료시각 |
| `endpoints` | 허용 경로 배열, 일반 이용자는 `["/mcp/rules"]`; 생략해도 규정 전용 경로만 허용 |
| `admin` | `true`인 관리용 자격증명만 `/status` 조회 가능; 일반 이용자에게 지정하지 않음 |

승인된 이용자 또는 그룹에 대한 발급 예시입니다. 경로는 실제 접근제한 운영 폴더로 바꾸고, 출력 토큰 파일은 해당 이용자에게 별도 보안 경로로 전달합니다.

```bash
npm run issue-token -- --id member-001 --registry /secure/dongguk/tokens.json --out /secure/dongguk/member-001.token --expires 2027-01-01T00:00:00Z
```

이 명령은 토큰을 보안 파일로, 해시는 등록 파일로 저장하기 위한 운영자 도구입니다. 파일 생성과 실제 이용자 발급·전달은 별도 기록합니다. 이 배포 가이드가 이용자 명부를 수집하거나 계정을 자동 개통하지는 않습니다.

토큰 파일은 서버 시작 시 읽습니다. 등록·변경·회수한 뒤에는 서버를 재시작하고 새 자격증명의 성공과 회수된 자격증명의 거절을 확인합니다. 등록 파일은 **최대 16,384항목·4MiB**를 지원하고 SHA-256 해시를 Map으로 조회합니다. 항목 수와 파일 크기 제한을 모두 만족해야 합니다. 운영자가 이용자별 또는 그룹별 발급을 선택할 수 있으며, 발급 대상·만료·회수 책임을 별도로 관리합니다. 기관 SSO·명부·자동 계정 회수와는 연결되어 있지 않습니다. 해시 파일도 접근제한을 유지하고 Windows에서는 서비스 계정의 파일 접근권한을 함께 설정합니다.

### 기존 관리자 연결을 등록 파일로 이전

`--token` 또는 `DONGGUK_MCP_TOKEN`을 함께 설정하면 기존 단일 토큰은 만료 없는 관리자 자격증명으로 추가됩니다. 같은 토큰의 해시가 등록 파일에도 있을 때는 이 기존 설정이 우선하므로, 등록 파일에서 `enabled:false`로 바꾸거나 만료시켜도 기존 설정이 남아 있으면 회수되지 않습니다.

운영자도 등록 파일의 활성화·만료·허용 경로로 관리하려면 다음 순서로 이전합니다.

1. 접근제한 환경에서 기존 토큰의 SHA-256 해시를 `operator` 같은 관리용 ID로 등록합니다. `admin:true`와 필요한 MCP 경로를 지정하고, 평문 토큰을 기록·출력하지 않습니다.
2. 서버 실행 설정에서 평문 `DONGGUK_MCP_TOKEN`의 export와 `--token` 인자를 제거합니다. 상위 환경에서 상속되지 않도록 실행 전에 `unset DONGGUK_MCP_TOKEN`도 적용합니다.
3. `--token-file` 또는 `DONGGUK_MCP_TOKEN_FILE`만 사용하는 상태로 재시작합니다. 기존 사용자에게 저장된 토큰 값은 바뀌지 않으며, 같은 해시의 등록 항목이 활성·허용된 동안 연결이 유지됩니다.
4. 별도 시험 자격증명의 비활성화·만료·경로 거절을 확인하고 운영자의 발급·회수 책임을 기록합니다.

CoP 초기 접속용 그룹 자격증명은 `/mcp/rules`만 허용하고 만료를 설정해 별도로 발급할 수 있습니다. 평문은 접근제한 로컬 파일로 저장해 정해진 이용 범위에 전달하고, 관리자 권한은 부여하지 않습니다. 그룹 자격증명 발급을 모든 구성원의 개별 계정 개통 또는 기관 SSO 연결로 보고하지 않습니다.

```bash
# 접근제한 서비스 설정에서 인증을 주입한 상태에서 실행
unset DONGGUK_MCP_TOKEN
node src/index.js --http --profile rules --host 127.0.0.1 --port 3845 --token-file /secure/dongguk/tokens.json
```

외부 공개는 HTTPS 프록시 또는 운영 중인 터널을 통해 `/mcp/rules`로 연결합니다. 프록시는 요청 크기·연결 제한과 인증 헤더 전달을 실제 환경에서 점검합니다. 직접 인터넷에 평문 HTTP를 노출하지 않습니다.

배포 후에는 다음 순서로 상태를 구분해 확인합니다.

1. `GET /health`로 프로세스와 배포 버전 확인.
2. 인증된 MCP 연결에서 `get_service_info`와 `tools/list` 확인.
3. `lookup_dongguk_rule`의 공개 규정 검색·원문·개정본 식별자 확인.
4. 구성원이 사용하는 실제 앱에서 같은 질문을 실행.
5. 다른 캠퍼스·직군의 대표 사용자가 적용범위 근거를 확인할 수 있는지 실증.

`/health`의 성공은 원문 서버, HWP 추출, 인증, 실제 앱 연결까지 정상이라는 뜻이 아닙니다. `GET /ready`는 프로세스의 요청 수용 상태만 확인하며, 관리용 인증이 필요한 `GET /status`는 집계 운영 상태를 확인하는 경로입니다. 서로 다른 검증 상태를 하나의 “전체 정상”으로 합치지 않습니다. 공개 endpoint에서 인증된 호출을 검증하지 못했다면 그 항목을 미검증으로 기록합니다.

## 5. 인증과 데이터 관리

- 구성원에게는 필요한 경로와 도구만 허용하고, 발급 대상·만료/회수일·담당자를 별도 기록합니다.
- 자격증명이 유출되면 즉시 폐기·재발급하고 영향 범위와 접속 기록을 확인합니다. 비밀값 자체를 사고 기록에 복사하지 않습니다.
- 로그에는 시각·버전·도구·지연·상태·오류코드를 우선 기록합니다. 질문 원문·인용 검증에 넣은 문서·응답 본문·쿠키·토큰을 기본 수집 대상으로 삼지 않습니다.
- 공개 `rules` 캐시와 인증된 원문/재무 서비스를 분리합니다. 로그인 쿠키가 필요한 사용은 선택한 `finance` 프로필과 승인된 범위에서만 운영합니다.
- 익명화되지 않은 내부 매뉴얼·급여·학생·신고자료를 공개 배포에 포함하지 않습니다. 검토된 재무지식팩도 공개 코드와 별도로 배포합니다.

## 6. 정기 확인과 용량 계획

### 운영자 장비 한 대로 운영하는 공용 서버

공용 서버는 운영자 장비 한 대(현재 맥스튜디오)에서 돌아갑니다. 이렇게 운영할 때는 서비스 프로세스뿐 아니라 전원·잠자기·로그인 이후 자동 실행·인터넷·HTTPS 터널의 상태를 함께 확인합니다. OS 업데이트나 재부팅 뒤에는 프로세스와 터널이 다시 시작하는지, 인증과 공개 원문 조회가 복구되는지 확인합니다. 로컬 컴퓨터의 잠자기 방지나 자동 실행 설정은 해당 장비의 운영 정책에 맞춰 별도로 관리합니다.

운영자 장비가 꺼지거나 잠자기에 들어가거나 인터넷이 끊기면 공용 MCP와 안내 페이지도 중단될 수 있습니다. 이런 환경에서 24시간 가용성 또는 SLA를 약속하지 않습니다. 장애 시 이용자는 공식 규정 시스템이나 개인 PC의 `rules` 설치 경로를 사용할 수 있지만 공식 원문 서버 자체가 장애인 경우 개인 설치로 해결되지는 않습니다.

공용 안내 페이지는 `/`와 `/guide`에서 제공하며 외부 스크립트·폰트·외부 자원을 불러오지 않는 `docs/quickstart.html`을 사용합니다. 내용은 인증 없이 주소만 넣는 공용 연결과 개인 PC 설치를 구분합니다. 안내 페이지 공개 자체가 기관 승인·전원 통지·계정 개통을 뜻하지 않습니다.

초기 CoP에서는 주 1회 운영자가 버전·대표 조회·원문 개정 이력·실패 기록을 확인하는 계획을 권합니다. 이 가이드 자체는 정기 자동화나 알림을 생성하지 않습니다.

여러 부서로 넓히기 전에는 대표 동시 사용자 수를 정하고 정상 요청·인증 실패·느린 원문·요청 제한 상황을 확인합니다. 서버 자원, 지연의 중앙값/상위 구간, 오류율, 원문 서버에 보내는 요청 수를 측정해 허용량을 정합니다. 코드의 동시 요청 제한과 캐시는 전교 규모 부하 검증 또는 SLA를 대신하지 않습니다.

규정 개정 발견 시에는 과거 근거 기록을 지우지 않고 새 HISTORY_ID와 조회일을 추가합니다. 이를 인용한 FAQ·교육 예시·질문카드를 재검토 대상으로 표시합니다. 개정본 ID 변경만으로 특정 금액·권한이 달라졌다고 공지하지 않습니다.

### 전문 색인 운영 (v0.13.0)

전문 색인은 전체 공개 규정의 HTML 본문을 조문 단위로 모은 파일입니다. `search_rule_deep`의 후보 탐색, `get_rule_references`의 역방향 조회, 그리고 규정명이 없는 자연어 질문에 대한 `lookup_dongguk_rule`의 후보 선정에 씁니다. 색인이 없어도 다른 도구는 그대로 동작하지만, 자연어 질문은 공식 사이트 전문검색(요청당 약 10초)으로 돌아가 느리고 복합어를 놓치기 쉽습니다.

```bash
dongguk-rule-mcp --build-index
```

- 2026-11-11 실측: 515개 규정, 약 4분 30초, 파일 약 6MB. 원문 서버에 0.5초 간격으로 요청합니다.
- 다시 실행하면 최신 개정본이 바뀐 규정만 다시 읽습니다.
- 파일 위치는 `~/.cache/dongguk-rule-mcp/v2/public/corpus/`입니다(`XDG_CACHE_HOME`을 지정하면 그 아래). 서버와 색인 명령이 같은 계정·같은 캐시 경로를 써야 합니다.
- 로그인 쿠키 없이 공개 규정만 색인합니다. 쿠키를 쓰는 `finance` 요청은 색인을 쓰지 않고 공식 사이트를 검색합니다.
- 공개용과 토큰용 프로세스는 같은 공개 캐시 폴더의 색인을 함께 읽습니다. 자동 갱신은 한 프로세스에만 지정합니다.
- 공용 HTTP 서버는 `DONGGUK_MCP_INDEX_REFRESH_HOURS=24`를 지정하면 기동 30초 뒤와 이후 24시간마다 스스로 갱신합니다. `/status`의 `fullTextIndex`에서 마지막 갱신 결과를 확인합니다.
- 규정 목록이 이전 색인보다 20% 넘게 줄면 색인을 덮어쓰지 않고 실패합니다. 일부 규정의 본문 조회가 실패하면 그 규정을 누락으로 기록하고 `complete:false`로 표시합니다.
- 색인이 8일을 넘기면 `search_rule_deep`은 공식 사이트 검색으로 돌아갑니다. `get_service_info`의 `fullTextIndex.stale`로 확인합니다. `lookup_dongguk_rule`은 오래된 색인도 후보를 찾는 데 쓰되 본문은 항상 현행 개정본을 다시 읽고, 결과에 색인 기준일과 "8일 초과"를 표시합니다.
- stdio로 쓰는 개인 설치(Claude Code·Claude Desktop 등)에는 자동 갱신이 없습니다. launchd 또는 cron으로 `dongguk-rule-mcp --build-index`를 주 1~2회 실행합니다. 예: `~/Library/LaunchAgents/com.dongguk-rule-mcp.build-index.plist`에 `ProgramArguments`로 `node <설치경로>/src/index.js --build-index`, `StartCalendarInterval`로 `Weekday 1, Hour 6`를 두고 `launchctl bootstrap gui/$(id -u) <plist>`로 등록합니다. 서버가 쓰는 계정·`XDG_CACHE_HOME`과 같아야 하며, 색인은 공개 규정만 담으므로 로그인 쿠키는 필요하지 않습니다.

## 7. 장애 대응

| 증상 | 확인 순서 | 이용자에게 안내할 상태 |
|---|---|---|
| 도구 연결 실패 | 앱 설정/재시작 → 실행 경로 → 서버/프록시 | 연결 실패, 규정 내용은 확인하지 못함 |
| `401` 인증 실패(`/mcp`) | 자격증명 발급·회수 → Bearer 전달 → 허용 경로 | 접근권한 확인 필요 |
| `429` 호출 제한 | `Retry-After` 확인 → 같은 IP를 쓰는 이용자 수 → 한도 조정 | 안내된 시간 뒤 재시도 |
| 요청 제한/과부하 | 동시 요청·요청량 → 재시도 간격 → 원문 지연 | 잠시 후 재시도, 결과 미확인 |
| 원문 HTTP 오류 | 공식 사이트 상태 → 운영 네트워크 → 재시도 | 원문 조회 실패, 오래된 답변을 최신으로 단정하지 않음 |
| HWP 실패·HTML 대체·빈 발췌 | 원문 파일 직접 확인 → 추출 경고·표 존재 확인 | 부분 조회, 표 근거 재확인 필요 |
| 잘못된 캠퍼스·직군·시행일 적용 | 해당 답변·근거 기록 → 업무 검토 → 재현 | 해당 흐름 수정 전 확산 중지 |
| 내부자료/자격증명 노출 | 노출 경로 중지·자격증명 회수 → 영향 확인 | 기관 사고대응 절차에 따라 안내 |

원문 장애를 근거 없이 “해외 IP 차단” 또는 “규정 없음”으로 확정하지 않습니다. 장애 중에는 [공식 규정 시스템](https://rule.dongguk.edu/)에서 사람이 원문을 확인하는 경로를 함께 안내합니다.

## 8. 롤백과 완료 판정

장애가 새 릴리스에서 재현되면 검증해 둔 직전 패키지와 설정으로 복구하고 프로세스를 재시작합니다. 복구 후 버전·프로필·인증·대표 원문 조회를 다시 확인합니다. 새 설정이 이전 버전과 호환되지 않을 수 있으므로 패키지뿐 아니라 해당 버전의 설정 백업도 사용합니다.

배포 보고에는 아래를 따로 씁니다.

- **완료:** 공개 릴리스·패키지·문서·검증 등 실제 증거가 있는 작업.
- **부분:** 로컬 또는 일부 경로에서만 확인한 연결·동작.
- **미검증:** 실제 구성원 앱, 캠퍼스/직군별 적용 실증, 동시 이용 규모, 업무시간 개선 등 아직 측정하지 않은 항목.
- **보류:** 기관 계정·승인·담당자 지정 등 외부 조건이 필요한 작업과 그 사유.

기관 SSO와 전 구성원 명부가 연결되어 있지 않으면 “전원 설치 완료”라고 보고하지 않습니다. [구성원 가이드](COP_GUIDE.md)와 [실증평가 양식](EVALUATION.md)을 배포하더라도 실제 통지·교육·계정 개통·효과 측정은 각 증빙으로 확인합니다.

## 법령 원문 연계와 개정 알림 (v0.14.0)

### 공개 프로필의 법령 원문 연계

`get_rule_references`에 `include_law_text=true`를 주면 규정이 인용한 국가 법령 조문의 현행 원문을 한국법령 MCP에서 함께 가져옵니다. `get_rule_upper_laws`의 법령 대조도 같은 연결을 씁니다. **법령 서버 주소나 키가 있으면 기본으로 켜집니다.** 공개 `rules` 프로필과 `finance` 프로필 모두 같습니다.

> 아래 표와 "타대학 비교" 절은 v0.15.10 기준입니다. v0.15.8 이하 설치본은 공개 프로필의 법령 연결에 `DONGGUK_LEGAL_MCP_ENABLED=1`·`DONGGUK_PUBLIC_LAW_LINK=1`이 필요하며, 원격 방식은 `DONGGUK_LEGAL_MCP_TRANSPORT=streamable-http`와 `DONGGUK_LEGAL_MCP_URL`을, 로컬 방식은 `LAW_OC`와 서버에 설치된 `korean-law-mcp`를 씁니다(`DONGGUK_LEGAL_MCP_TRANSPORT`는 생략하거나 `stdio`). 타대학 비교에는 `DONGGUK_UNIVERSITY_COMPARISON_ENABLED=1`이 필요합니다. 바뀐 내용은 [변경 기록](../CHANGELOG.md)의 v0.15.10 항목에 있습니다.

| 환경 변수 | 값 |
|---|---|
| `DONGGUK_LEGAL_MCP_URL` | 한국법령 MCP 주소(https). 이 값만 있으면 `streamable-http`로 연결합니다 |
| `LAW_OC` | 주소 대신 쓰는 방식. 법제처 Open API 인증키(OC)이며, 서버에 `korean-law-mcp`가 설치되어 있어야 합니다(stdio) |
| `DONGGUK_LEGAL_MCP_TRANSPORT` | 생략하면 주소가 있을 때 `streamable-http`, 없으면 `stdio`. 직접 지정할 수도 있습니다 |
| `DONGGUK_LEGAL_MCP_BEARER_TOKEN` | 법령 서버가 인증을 요구할 때만. 접근제한 설정으로 주입합니다 |
| `DONGGUK_LEGAL_MCP_API_KEY` | 호스팅 한국법령 MCP(예: `mcp.gomdori.app/law`)에 운영자의 법제처 OC를 `apikey` 헤더로 넘깁니다. 없으면 그 서버의 공용(무키) 한도를 씁니다. 응답·로그에 값을 내보내지 않습니다 |
| `DONGGUK_LEGAL_MCP_ENABLED` | 생략하면 켜짐. `0`이면 모든 프로필에서 법령 연결을 끕니다 |
| `DONGGUK_PUBLIC_LAW_LINK` | 생략하면 켜짐. `0`이면 공개 `rules` 프로필과 `/mcp/rules`에서만 법령 연결을 끕니다 |

- 주소와 키가 모두 없으면 오류를 내지 않습니다. `lawTexts.status`(또는 `lookup.status`)가 `not_configured`로 나오고, `notice`와 `setup`에 무엇이 없는지·어떤 환경변수를 넣으면 되는지·OC 신청처(open.law.go.kr)를 담아 돌려줍니다. 규정 인용 결과는 그대로 반환합니다.
- 기본 법령 서버 주소는 코드에 들어 있지 않습니다. 운영자가 쓸 주소를 직접 넣습니다.
- 이전 버전에서 `DONGGUK_LEGAL_MCP_ENABLED=1`·`DONGGUK_PUBLIC_LAW_LINK=1`을 넣어 둔 서버는 그대로 동작합니다. 두 값을 넣지 않고 주소나 `LAW_OC`만 있던 서버는 이번 버전부터 법령 연결이 켜지므로, 끄려면 `0`을 넣습니다.
- 조문이 특정된 인용만, 한 번에 8개 조문·조문당 6,000자까지 가져옵니다. 전체 35초 안에 끝나지 않으면 가져온 것만 반환합니다.
- `get_rule_upper_laws`는 한 번에 법령 `max_laws`개(최대 12)까지 확인하고, 남은 법령은 버리지 않고 `page.nextOffset`을 `law_offset`에 넣어 이어서 확인합니다.
- **법령 응답 캐시:** 법령 서버의 성공 응답을 도구 구분 없이 디스크에 공유 저장합니다. 현행 법령 목록(`search_law`)·별표는 같은 날(한국 시간) 6시간, MST로 고정된 조문 본문(`get_law_text`)은 30일, 과거 기준일 판정(`legal_analysis`)은 7일입니다. MST는 공포된 한 버전을 가리키므로 법령이 개정되면 목록의 MST가 바뀌어 새 본문을 받습니다. 오류·빈 응답·점검 화면·"없음" 응답은 캐시하지 않습니다. `DONGGUK_MCP_NO_CACHE=1`이면 끕니다.
- **한도 초과 재시도:** 법령 서버가 429(요청 한도 초과)를 돌려주면 `Retry-After`(최대 5초) 또는 0.5초·1초 간격으로 두 번까지 다시 시도하고, 그래도 막히면 `LEGAL_UPSTREAM_RATE_LIMITED`로 표시합니다. 전체 제한 시간을 넘겨 기다리지 않습니다.
- **이용 한도:** 공개 주소의 IP별 제한(분당 60·하루 1,000)이 이 서버로 들어오는 요청의 상한입니다. 호스팅 한국법령 MCP를 키 없이 쓰면 그 서버의 공용 한도(접속 IP마다 분당 60회, 키 없는 사용자 전체가 나눠 쓰는 전역 한도)를 탑니다. 공용 서버는 모든 사용자의 법령 조회가 한 IP로 나가므로 `DONGGUK_LEGAL_MCP_API_KEY`로 운영자 OC를 넘기거나, `LAW_OC`로 서버에 설치한 `korean-law-mcp`(stdio)를 써서 운영자 키 한도로 조회하는 편이 안전합니다. 법제처 Open API 쪽 한도는 [국가법령정보 공동활용](https://open.law.go.kr)의 신청 정보에서 확인합니다.
- `get_service_info`의 `integrations.legalCalls`가 `quota`(`own_key`: 이 서버가 운영자 키를 넘김, `local_operator_key`: 같은 컴퓨터(loopback 주소)에서 운영자 `LAW_OC`로 띄운 `korean-law-mcp` 사용, `shared_keyless`: 원격 호스팅 서버의 공용 무키 한도), 캐시 적중·실제 호출·재시도 횟수(프로세스 시작 이후)를 보여 줍니다. 키 값은 나오지 않습니다.
- `get_service_info`의 `integrations.lawLink`로 상태를 확인합니다. `state`는 `ready`(켜짐), `missing`(주소·키 없음), `invalid`(값 오류), `disabled`·`disabled_public`(운영자가 끔)입니다.

### 타대학 비교

`compare_university_rules`는 기본으로 켜져 있습니다. 끄려면 `DONGGUK_UNIVERSITY_COMPARISON_ENABLED=0`을 넣습니다. 서울대만 법제처 Open API 인증키(`DONGGUK_LAWGO_OC`, open.law.go.kr에서 신청)가 필요하며, 키가 없으면 서울대 열에만 안내를 붙이고 나머지 대학은 그대로 비교합니다. 상태는 `get_service_info`의 `integrations.universityComparison`(`configured`, `snuKeyConfigured`)으로 확인합니다.

### 주간 개정 알림

`npm run weekly-updates`는 지난 7일간 개정된 규정과 변경된 본칙 조문을 정리합니다. 규정 10건 안팎이면 20초쯤 걸립니다.

```bash
node scripts/weekly-updates.js --format slack          # 내용만 출력
DONGGUK_SLACK_WEBHOOK_URL=... node scripts/weekly-updates.js --post
```

- `--days 14`, `--since 2026-11-01`로 기간을 바꿉니다. 개정이 없으면 게시하지 않으며 `--post-empty`로 게시할 수 있습니다.
- 웹훅 주소는 `https://hooks.slack.com/`만 받습니다. 접근제한 환경파일에서 주입하고 명령행·문서에 적지 않습니다.
- 매주 월요일 9시에 실행하려면 launchd `StartCalendarInterval`(Weekday 1, Hour 9) 또는 cron `0 9 * * 1`에 등록합니다.
- 변경 조문은 본문 비교 결과입니다. 별표·서식 변경은 "본칙 조문 변경 없음"으로 나옵니다. 개정일은 공식 사이트 기준이며 시행일과 다를 수 있습니다.

## 공개 엔드포인트 호출 제한

토큰 없이 호출하는 요청은 클라이언트 IP별로 제한합니다. Cloudflare Tunnel 뒤에서는 loopback 피어에서 온 `CF-Connecting-IP`만 신뢰합니다. 토큰 보유자는 멤버 레지스트리로 관리하므로 IP 제한에서 제외합니다.

| 환경 변수 | 기본값 | 설명 |
|---|---|---|
| `DONGGUK_MCP_RATE_LIMIT_PER_MINUTE` | 60 | IP별 분당 호출 수. 0이면 해제 |
| `DONGGUK_MCP_RATE_LIMIT_PER_DAY` | 1000 | IP별 24시간 호출 수. 0이면 해제 |
| `DONGGUK_MCP_TRUST_PROXY` | 1 | 0이면 `CF-Connecting-IP`를 무시 |

초과 시 HTTP 429와 `Retry-After`(초)를 반환합니다. `/health`, `/ready`, 안내 페이지는 제한하지 않습니다. 이 서비스는 동국대학교의 공식 서비스가 아니며, `get_service_info`와 MCP `instructions`에 같은 안내가 포함됩니다.

## 타대학 주간 스모크와 사용 로그

`npm run university-watch`는 동국대를 제외한 19개 대학 로더를 직접 호출합니다. 각 대학에 「여비」 단일 검색어와 대표 규정 최대 1개를 요청하며, 동국대 재조회·상시 적재·백그라운드 크롤링은 하지 않습니다. 목록 구조에 따라 검색·규정명 재확인·상세·본문 요청이 더 필요할 수 있습니다. 전체 60초, 대학당 15초, 요청당 최대 8초, 대학별 500ms 간격을 유지합니다. 서로 다른 대학은 최대 5곳을 동시에 처리하고 PDF worker는 최대 2개입니다. 시간 초과는 `TOTAL_TIMEOUT`으로 남기고 자동 재시도하지 않습니다. 일반 비교의 최대 규정 수 5개와 공통/세종 목록 캐시 TTL 10분은 그대로입니다.

```sh
# 첫 실행은 기준 스냅샷 생성. 다음 실행은 같은 파일의 직전 결과와 비교 후 원자적으로 교체.
npm run university-watch -- --snapshot /local/private/university-watch.json
# 명시한 이전 파일과 비교, 새 스냅샷은 별도 저장
npm run university-watch -- --previous /local/private/previous.json --snapshot /local/private/current.json --format json
# 무게시 Slack 포맷 미리보기
npm run university-watch -- --format slack
# 외부 요청 없이 최근 7일의 비교 실패 집계만
npm run university-watch -- --usage-only --usage-dir /local/private/usage --days 7
```

기본 출력은 Markdown이며 `--format markdown|slack|json`을 지원합니다. 성공은 대표 조문 조회 성공입니다. `partial`도 실패 코드 없이 대표 조문을 읽었다면 성공으로 집계하지만 전문·별표·전체 개정 여부를 확인했다는 뜻은 아닙니다. 무결과·현행본 미확인·차단·타임아웃·서울대 OC 미설정은 실패 코드로 구분합니다. 서울대는 기존 `DONGGUK_LAWGO_OC`가 있을 때만 조회하며 키를 기록하거나 설정하지 않습니다.

스냅샷에는 KST 시각·대학·규정명·개정일·시행일·시행 예정일·상태·실패 코드·소요 시간과 조문 앞부분 8,192 UTF-16 코드 단위(공백 정규화 후)의 SHA-256만 저장합니다. 본문은 저장하지 않습니다. 개정일은 어댑터가 확인한 값만 기록하고 없으면 미확인으로 둡니다(본문의 임의 날짜로 대신하지 않음). 제목에 주제어가 없는 대표 규정은 `TOPIC_TITLE_NOT_MATCHED`로 별도 표시하므로 전담 규정인지 확인해야 합니다. `REVISION_DATE_CHANGED`·`BODY_HASH_CHANGED`는 개정 추정 신호이며 법적 확정이 아닙니다. `UPCOMING_REVISION`, 대표 규정 교체, `UPSTREAM_FORMAT_CHANGED`, `PDF_REVISION_UNVERIFIED`, 연속 실패 및 회복을 따로 표시합니다. 실패 중에도 마지막 성공의 메타데이터·해시만 유지하므로 회복 후 변경을 비교할 수 있습니다. 대상 규정 외 개정은 탐지하지 못합니다.

Slack은 `scripts/weekly-updates.js`와 같은 `postToSlack` 함수와 `DONGGUK_SLACK_WEBHOOK_URL`을 사용합니다. HTTPS `hooks.slack.com`만 허용하고 리다이렉트·URL 출력은 금지합니다. **`--post`를 명시해야만 실제 게시**합니다. 이 기능의 설치·검증 단계에서는 `--post` 없이 출력만 확인합니다. 새 채널·웹훅은 필요하지 않습니다.

HTTP 서버에 `DONGGUK_MCP_USAGE_LOG_DIR`가 설정되어 있을 때만 파싱된 `tools/call` 응답 종료 후 `usage-YYYY-MM.jsonl`을 비동기로 기록합니다(디렉터리 0700·신규 파일 0600). 시각·소요 시간·HTTP/처리 상태·대학 키·대학별 실패 코드만 남깁니다. 비교 도구 외 이름은 `other`로 묶고 입력 인자·IP·토큰·쿠키·웹훅·규정 제목·본문은 남기지 않습니다. 인증/요청 파싱 전에 거절된 호출은 대상에서 제외됩니다. 8MiB 초과 응답은 캡처하지 않고 `unobserved`로 표시합니다. 로그 쓰기 실패·큐 포화는 응답에 영향을 주지 않으며 감시 목적상 기록 누락이 있을 수 있습니다.

집계는 기본 7일(`--days 1..366`)이며 환경변수 디렉터리를 쓰거나 `--usage-dir`로 지정합니다. 한 대학의 같은 실패 코드는 호출당 한 번만 셉니다. 파일/기간 내 비교 로그가 없으면 “로그 없음”, 손상 줄과 대학 결과가 없는 구버전 로그는 별도 건수로 표시합니다. 권한 오류는 빈 로그로 숨기지 않습니다. 로그는 운영자가 로컬 보관·삭제 정책을 정하며 본 CLI는 기존 로그를 수정하지 않습니다.

예약 실행은 예를 들어 **월요일 06:00 KST**로 계획할 수 있습니다. 실행 호스트 시간대가 Asia/Seoul인지, 기존 동국대 색인 작업과 겹치지 않는지 확인한 뒤 별도 승인으로 등록합니다. launchd `StartCalendarInterval` 예시는 `{ Weekday: 1, Hour: 6, Minute: 0 }`이며 `ProgramArguments`는 절대 경로의 `node`, `scripts/university-watch.js`, `--snapshot`, 로컬 스냅샷 경로입니다. 이 PR은 launchd 등록·공용 서버 런처 변경·실제 게시를 수행하지 않습니다.

## 질문 로그와 노션 동기화

`DONGGUK_MCP_QUERY_LOG_DIR`를 넣은 HTTP 서버만 검색·조회 도구의 질문 문자열을 개인정보를 가린 뒤 `queries-YYYY-MM.jsonl`(0600)에 남깁니다. 노션 업로드는 서버 밖의 `scripts/sync-query-log-notion.js`가 맡습니다. 저장 필드, 마스킹 규칙, 노션 데이터베이스 속성, 보관 기간(기본 1년)과 삭제 방법, 런처 변경은 [QUERY_LOG.md](QUERY_LOG.md)를 따릅니다. 서버 반영과 동기화 예약 등록은 별도 승인으로 합니다.
