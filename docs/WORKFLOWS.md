# 동국 규정 MCP 업무 활용

규정을 찾은 결과를 지급 검토·기안·감사 근거로 남기는 실무 흐름입니다. 아래 질문은 예시이며 지급 가능 여부나 특정 금액을 확정한 사례가 아닙니다.

## 시작과 공통 원칙

처음 연결하거나 업데이트한 뒤 `get_service_info`를 호출해 버전·프로필·도구 수를 확인합니다. 평소 단일 규정 질문은 `lookup_dongguk_rule`부터 사용하고, 충분한 근거를 받았으면 검색·목차·본문을 반복 조회하지 않습니다.

- 질문에는 소속·캠퍼스, 교원/직원 등 신분, 업무 종류, 적용 기준일을 적습니다. 이름·개인번호·계좌는 필요하지 않습니다.
- `campus:"seoul"` 등은 업무 맥락입니다. 캠퍼스 자동필터가 아니므로 법인·서울·WISE·산학협력단과 신분별 적용범위를 원문에서 확인합니다.
- `AMBIGUOUS_RULE`이면 후보의 정확한 규정명과 적용범위를 확인하고, 반환된 `LAW_ID`를 `law_id`에 넣어 다시 조회합니다. 식별번호를 추측하지 않습니다.
- 현재 `lookup_dongguk_rule` 입력에는 기준일 매개변수가 없습니다. 과거 적용 검토는 `applicable_rule`을 사용합니다.

## 1. 급여·수당 지급 근거 찾기

> 서울캠퍼스 직원에게 수당을 지급하려고 해. 동국규정에서 보수·수당 관련 규정 후보를 찾아 적용 대상, 지급 요건, 예외, 관련 조문·별표를 정리해줘. 규정에 없는 금액은 만들지 말고, 정확한 규정명과 원문 링크를 보여줘.

기본 조회 예시:

```json
{"query":"서울캠퍼스 직원의 보수와 수당 지급 요건을 확인하고 싶다","rule_keyword":"보수","terms":"직원,수당,지급,적용","campus":"seoul"}
```

후보가 여러 개면 대상 신분에 맞는 규정을 먼저 고릅니다. 산출물은 **지급 요건 / 예외·제한 / 근거 위치 / 추가로 확인할 사실** 네 칸으로 정리합니다. 과세·원천징수는 국가 법령, 실제 지급액·공제액은 급여 시스템과 별도로 대조합니다.

## 2. 출장비·별표의 금액과 조건 확인

> 서울캠퍼스 직원의 국내 출장 숙박비 기준을 찾아줘. 여비규정의 관련 조문과 별표에서 직급·지역별 행, 금액 단위, 상한, 실비 조건, 주석을 함께 보여줘. 표가 잘렸거나 병합 셀을 읽지 못했으면 확인할 원문 위치를 알려줘.

```json
{"rule_keyword":"여비규정","query":"국내 출장 숙박비의 상한과 실비 정산 조건","terms":"국내,숙박비,실비,별표","campus":"seoul","max_sections":6,"max_chars":18000}
```

`evidenceStatus`, `incompleteReasons`와 발췌를 함께 봅니다. 블록 수·글자 수 제한으로 필요한 부분이 빠졌으면 핵심어를 좁히거나 `max_sections`·`max_chars`를 늘려 재조회합니다(설정 상한 12·30,000, 표의 앞뒤 문맥은 추가될 수 있음). 추출된 표의 행·열·단위가 불명확하면 원문 표를 확인한 뒤 계산합니다.

## 3. 위임전결과 결재 경로 검토

> 서울캠퍼스 교비회계에서 물품을 구매하려고 해. 위임전결규정의 구매·계약·지출 관련 별표를 찾아 업무 유형, 금액 구간, 전결권자, 합의·예외 조건을 정리해줘. 거래금액 등 필요한 사실이 부족하면 확인사항으로 남겨줘.

```json
{"rule_keyword":"위임전결규정","query":"물품 구매 계약과 지출의 금액별 전결 및 합의 조건","terms":"구매,계약,지출,전결,합의","campus":"seoul","max_sections":8,"max_chars":22000}
```

산출물에는 **업무 항목 → 금액 구간 → 전결권자 → 합의·예외 → 별표 위치**를 남깁니다. 금액의 부가세 포함 여부나 회계단위가 불명확하면 전결권자를 확정하지 않습니다. nDRIMS의 현재 결재선 설정과 실제 결재 완료는 규정 조회만으로 확인되지 않습니다.

## 4. 과거 지급·감사 건의 기준일 검토

> 2025년 3월 15일 국내 출장 건을 감사 검토 중이야. 당시 여비규정 후보와 현행 규정의 차이를 찾아줘. 개정일과 부칙의 시행일·경과조치를 구분하고, 숙박비 별표도 비교해줘. 해당 날짜에 실제 적용됐는지 확인되지 않은 부분은 남겨줘.

```json
{"rule_keyword":"여비규정","date":"2025-03-15","compare_with_current":true}
```

위 입력은 `applicable_rule` 호출 예시입니다. 반환된 규정과 과거 개정본 후보를 확인한 후:

1. 필요하면 `list_rule_history`에 반환된 `law_id`를 넣어 연혁을 확인합니다.
2. `compare_rule_versions`에 같은 규정의 `law_id`와 확인한 `from_history_id`를 넣고 `include_appendices:true`로 호출합니다. `to_history_id`를 생략하면 최신본과 비교합니다.
3. `get_rule_content`에 해당 `law_id`, `history_id`, `article:"부칙 제2조"`처럼 실제 확인할 조문을 지정해 시행일·경과조치를 보완합니다. 조문 번호는 해당 규정의 목차·본문에서 확인합니다.

**개정일은 시행일과 같지 않습니다.** 기준일 이전 개정본 선택은 적용 후보를 찾는 단계입니다. v0.12.0은 HWP 조문을 우선 비교하고 별표·서식의 텍스트, 표 셀의 좌표·행/열 병합 범위·값, 포함된 그림 파일의 내용 변경을 함께 확인합니다. HWP 실패로 HTML 조문을 사용했으면 부분 비교로 남깁니다.

결과를 기록할 때는 변경된 셀의 행·열·값과 병합 범위, 문서별 추출 진단을 함께 남깁니다. 그림 파일의 해시가 달라졌다는 결과만으로 그림 속 문구나 의미가 어떻게 변했는지는 확정하지 않습니다. 실제 미지원 객체·누락·식별 모호성이 남은 부분을 “변경 없음”으로 기록하지 않습니다.

## 5. 기안문·품의서의 규정 인용 점검

> 아래 비식별 기안문에서 규정명·조문·제목·항 번호가 실제 존재하는지 확인해줘. 일치, 불일치, 확인 불가를 나누고, 수정이 필요한 인용은 원문 근거와 함께 제안해줘. 본문에 인용이 없으면 검증할 인용 없음으로 알려줘.

`verify_rule_citations`의 `text`에 실제 검토할 문장을 그대로 넣습니다. 아래 자리표시자를 실제 문장으로 교체합니다.

```json
{"text":"[개인정보를 제거한 실제 기안문 본문]","campus":"seoul"}
```

입력은 20,000자 이하입니다. 규정명은 `「규정명」 제N조(조문 제목) 제N항`처럼 명확히 표기하면 대조가 쉽습니다. 인용 실존 확인은 사안의 적정성·지급 승인과 다릅니다. 인용이 0건이거나 조회에 실패한 경우도 검증 통과로 취급하지 않습니다.

## 결과에 함께 남길 근거

| 항목 | 남길 내용 |
|---|---|
| 업무 조건 | 캠퍼스·소속·신분·회계단위·거래/출장/지급 기준일 |
| 규정 식별 | 정확한 규정명, `LAW_ID`, `HISTORY_ID` |
| 원문 위치 | 조문·항·별표 번호, 표의 행·단위·주석, 원문 URL |
| 시점 | 개정일, 확인한 시행일·경과조치, 조회일 |
| 확인 수준 | `ok`, 오류 코드, `evidenceStatus`, 부분 조회 사유·대체 출처 |
| 검토 결론 | 확인된 근거, 조건부 판단, 담당자가 추가 확인할 사항 |

`retrieved`는 발췌 확보를 뜻하며 완전한 원문 검증이나 적용 확정이 아닙니다. `partial`, 빈 발췌, HTML 대체, 검색어 미일치, 표 잘림은 답변에도 표시합니다.

## 공개 규정과 내부 재무 업무의 연결

기본 **`rules` 프로필은 공개 규정 10개 도구**입니다. 위 다섯 업무의 규정 근거 조회에 사용합니다. 내부 매뉴얼·해설서·지급 내역을 포함하지 않습니다.

**`finance` 프로필은 14개 도구**이며 네 도구가 추가됩니다. `get_finance_context`는 업무 조건과 절차, `get_finance_evidence`는 출장·강사료·소득정정 등의 근거 묶음, `search_finance_handbook`은 해설, `review_finance_case`는 계정·증빙·기안문 검토에 사용합니다. 실제 자료팩과 법령 연결이 준비된 범위에서만 활용합니다.

규정 MCP는 원문 조회, 재무 온톨로지팩은 업무 조건·절차, Finance Desk는 근거를 모아 검토하는 이용 창구입니다. 일반 직원용 공개 규정 조회와 재무팀원용 내부 자료 접근을 구분합니다. 내부 자료팩은 공개 저장소·패키지에 넣지 않으며, 조회 결과만으로 신고·지급·결재가 실행되지는 않습니다.

연결·자료팩 설정은 [Finance Desk 안내](FINANCE_DESK.md), 빠른 조회는 [성능·사용 안내](PERFORMANCE.md), 운영은 [운영 가이드](OPERATIONS.md)를 참고하세요.
