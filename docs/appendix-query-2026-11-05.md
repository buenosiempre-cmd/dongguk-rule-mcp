# 별표 자연어 조회 수정

v0.12.2, 2026-11-05.

## 재현과 변경

v0.12.1에서 `query: "여비규정 별표를 보여줘"`를 호출하면 원문 HWP의 표 3개·셀 189개를 정상 추출하고도 `NO_MATCHING_EXCERPT`를 반환했다. 검색어 `별표를`과 원문 제목 `< 별 표 1 >`을 같은 선택자로 처리하지 못했다. 키워드로 표를 찾더라도 표 다음 한 문단만 보존하므로 여러 문단의 주석이 빠질 수 있었다.

- `별표를`, `별 표 제1호`, `별표 1의2`를 인식한다. 별표 1·10·1의2는 구별한다.
- 원문에 포함된 별표의 제목·표·주석을 하나의 검색 단위로 반환한다. 다음 별표나 본칙·부칙 경계에서 멈춘다.
- 조문과 별표를 함께 요청할 수 있다. 국내·국외가 명시된 별표 제목을 기준으로 범위를 구분하며, 주석의 다른 별표 참조가 선택 범위를 넓히지 않는다.
- 요청한 별표 본체가 없으면 `excerpt.missingAppendices`와 `APPENDIX_NOT_FOUND`로 `partial`을 표시한다. 본문 참조 문구만 찾은 것은 별표 조회 완료가 아니다.
- 블록·글자 수 제한은 기존처럼 생략 여부를 표시한다. `partial`은 지원 불가와 동의어가 아니며, 원인에 따라 한도 확대나 원문 확인이 필요하다.
- 검색 결과의 후속 안내도 HWP를 읽는 `lookup_dongguk_rule`을 우선하도록 맞췄다.

## 지원 범위와 남은 기능

현재 읽는 대상은 `FILE_TYPE=ori`의 원문 HWP다. [여비규정 공식 화면](https://rule.dongguk.edu/lmxsrv/law/lawFullView.srv?SEQ=184&SEQ_HISTORY=3350)의 최신 확인 개정본은 HISTORY_ID 3350, 개정일 2025.04.29이며 원문에 별표 1·2·3이 포함돼 있다.

공식 사이트의 제목·첨부 화면에는 별표 1·2·3 HWP가 별도 파일로도 등록돼 있지만, `FILE_TYPE=attach` 첨부를 자동 탐색·다운로드하는 기능은 아직 없다. 원문에 없는 별도 첨부 HWP/PDF/HWPX 및 그림·스캔의 OCR은 이번 범위에 포함하지 않는다. 첨부 목록·파일별 출처·지원 형식·추출 실패 표시를 갖춘 별도 첨부 조회가 후속 기능 후보이다.

`get_rule_content`는 HTML 본문 조회 도구이므로 별표 조회에는 `lookup_dongguk_rule`을 사용한다. 특정 클라이언트에서 실패한 이유는 실제 도구 호출·연결 서버·응답을 확인해야 하며, 위 재현만으로 특정 봇의 호출 경로까지 확정하지 않는다.

## 검증과 적용

- `npm test` 전체 오프라인 검사 통과. 별표·통합 조회 30개와 유지보수 MCP 회귀 16개를 포함해 자연어·정확한 번호·가지번호·조문 복합 요청, 여러 주석 보존, 국내·국외 구분, 없는 별표 본체, 길이 제한을 검증했다. 최종 도구 설명의 MCP 프로토콜 검사 32개도 통과했다.
- `node test/smoke-appendices-live.js` 실원문 5가지 검사 통과(캐시·로그인 쿠키 미사용, LAW_ID 184 / HISTORY_ID 3350). 전체 별표 1·2·3, 별표 1만, 국외 별표 2·3만, 없는 별표 99를 구분했다. 별표 1의 주석 ①~⑥을 확인했다. 기본 한도에서는 별표 3개가 포함돼도 일부 관련 조문 생략으로 `partial`이며, 한도를 늘리면 `retrieved`였다.
- GitHub 소스 병합, 로컬 설치, 실행 중인 MCP 연결, 공용 HTTP 서버 배포는 서로 다른 상태다. v0.12.2 소스만으로 슬랙 연결 서버가 갱신됐다고 판단하지 않는다.
