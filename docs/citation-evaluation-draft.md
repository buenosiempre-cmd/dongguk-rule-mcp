# 인용 점검 공개 채점 셋 초안

`verify_rule_citations`의 **출처 귀속과 판정 상태**를 채점하는 공개 개발용 20문항이다. 이미 본 재현 사례가 포함되어 있으므로 비공개 평가나 일반 정확도 추정에 쓰지 않는다. 근거와 기대값을 검수자가 독립 확인한 뒤 확정할 초안이다. 법적 적용 적합성은 채점하지 않는다.

## 근거와 범위

- 2026-11-28 Dongguk Rule MCP `get_rule_content(law_id=184, article=제9조)`·`제13조`로 받은 [여비규정 원문](https://rule.dongguk.edu/lmxsrv/law/lawFullView.srv?SEQ=184&SEQ_HISTORY=3856)을 고정했다. LAW_ID 184, HISTORY_ID 3856, 개정일 2026-03-13. **시행일은 별도 미확인**이다. 전문이 아닌 두 조문 발췌이므로 다른 조문이 없다는 판정에는 사용하지 않는다.
- 한국법령 MCP `get_law_text(mst=290777, jo=제29조)`: 사립학교법 제29조(회계의 구분 등), 시행일 2026-10-02. 도구의 기대값은 외부 법령 경고이며 국가 법령 조문을 이 도구로 검증했다는 뜻이 아니다.
- 한국법령 MCP `get_law_text(mst=270757, jo=제13조)`: 사학기관 재무ㆍ회계 규칙 제13조는 삭제 조문이다. 검색 응답의 시행일 2025-07-19와 본문 응답의 2025-04-18이 달라 **시행일 미확인**으로 기록한다. 이 문항은 여비규정 제13조로 잘못 판정하지 않는지만 채점한다.
- 상세 인용·문단 경계의 기대값은 [인용 도구 계약](REFERENCE.md)에 따른다. 교내 이름에 법이 들어간 경우, 정확한 교내 규칙 제목, 일반 명사, 시행령·시행규칙, 검색 실패는 별도 `test/test-citations.js`의 합성 대조군으로 보완한다.

## 재현과 채점

```sh
node scripts/evaluate-citations.js
node scripts/evaluate-citations.js /path/to/baseline/src/citations.js
node test/test-citations.js
npm test
```

첫 인자가 없으면 현재 코드, 있으면 지정한 기준 코드의 `verifyRuleCitations`를 사용한다. 고정 조문과 검색 응답만 사용하므로 네트워크 호출은 없다. 각 문항의 `ruleName`, `article`, `status`, `verified`, `notFound`, `needsReview`, `total`, `floating`을 모두 대조한다. 삭제된 문항이나 빈 결과가 성공으로 집계되지 않으며 하나라도 다르면 종료 코드 1이다. 항의 세부 실존은 별도 단위 테스트가 보완한다.

초안 v1은 main `ee501b6` 15/20 → PR #87 `2991d6d` 20/20이었다. A2 후속의 v2는 입력을 유지하고 CIT11·20의 외부 규칙 기대 상태를 `EXTERNAL_LAW`에서 `CITATION_SOURCE_UNVERIFIED`로 바꿨다. 규칙이라는 접미사와 교내 검색 미일치만으로 국가 법령으로 분류하지 않는 계약 변경이다. 두 상태 모두 verified 0인 경고이며, 이 상태명 변경을 정확도 향상으로 계산하지 않는다. v2 기대값 기준 #87은 18/20, A2는 20/20이다.

## 남은 한계

명칭을 먼저 보존하므로 조문까지의 연결 표현을 모두 해석할 필요는 없지만, 명칭 자체가 어휘 경계로 인식되어야 한다. 긴 명칭은 앞쪽 최대 8개 단어를 수집하며 접속사·서술 표현에서 멈춘다. 임의의 명칭 오기와 모든 붙임·띄어쓰기 변형을 해석하지 않는다. 별칭 괄호는 앞 명칭을 보존하지만 뒤에 단독 사용한 별칭을 자동 해소하지 않는다. 알려진 접두 서술어만 제거하고, 불명확한 명칭은 부분 일치로 성공시키지 않는다. 명시적인 새 명칭 없이 본칙으로 돌아가는 서술은 앞 외부 출처의 경고를 유지할 수 있다. 국가 법령 존재를 확인하는 API 호출은 추가하지 않는다.

후속으로 별도 작성자가 새로운 규정·주제를 선택하고 기대 조문을 MCP 원문과 대조하여 공개 개발 셋을 늘려야 한다. 비공개 보류 문항에는 접근하지 않았다.
