# I02·I03 공통 반영 계약

## 반영 순서·상태 이름 정의 주체 (공통 계약)

**반영 순서는 I02 #68 → I03 #70이다.** 현재 두 PR은 각각 main `d08ef02`에서 출발한 독립 draft다. 실제 병합·배포는 수행하지 않았다. I03 반영 시에는 I02가 적용된 최신 main을 가져와 충돌을 해결하고, 두 테스트 묶음을 함께 재실행해야 한다. 강제 push는 사용하지 않는다.

| 상태/계약 | 정의하는 PR | 의미·집계 |
|---|---|---|
| `ARTICLE_SELECTOR_UNVERIFIED` | **I02 #68** | 날짜 부칙 선택자를 공통 파서로 해석할 수 없음. `⚠`, `verified=0`, `exists=0`, `needsReview=1`. |
| `UNSUPPORTED_CITATION` | **I03 #70** | 별표·서식·호·목·지원 범위 밖 번호 등 인용에 미지원 부분이 있음. `⚠`, `verified=0`, `exists=0`, `needsReview=1`. |
| `NOT_FOUND`, `ARTICLE_AMBIGUOUS`, 기존 `RULE_*`/`HANG_*` | 기존 계약 유지 | 새로운 의미로 재사용하거나 이름을 바꾸지 않는다. |
| `originalRange`, `parsedRange`, `unsupportedReasons`, 명시적 성공 집계 | **I03 #70** | 새 필드를 더하며 기존 summary 키는 유지한다. I02 자체는 summary 코드를 바꾸지 않고 기존 기호별 집계를 따른다. |

겹치는 파일은 `src/citations.js`, `src/index.js`의 도구 설명, `test/test-citations.js`다. 재현 스크립트와 이 통합 안내 파일은 동일한 내용으로 두 PR에 추가되어 있다. 추출 정규식뿐 아니라 선택자 필드·중복 제거 키·판정 우선순위·도구 설명을 함께 조정해야 한다.

통합 시 I03의 전체 숫자/범위 보존을 유지하고, 날짜 부칙 접두부는 I02의 `normalizeArticleSelector`로 처리한다. 정상 날짜 부칙을 I03 독립 브랜치의 `UNSUPPORTED_ADDENDUM_SELECTOR`로 계속 차단해서는 안 된다. 날짜·조문이 없는 경우에는 I02의 `NOT_FOUND`, 해석할 수 없는 날짜 표기는 I02의 `ARTICLE_SELECTOR_UNVERIFIED`, 날짜 없는 복수 부칙은 기존 `ARTICLE_AMBIGUOUS`를 유지한다. 별표·호·목·범위 밖 번호가 함께 있으면 I03의 `UNSUPPORTED_CITATION`을 우선 적용한다. 어느 경우에도 일부 본칙 실존만으로 성공 처리하지 않는다.

I02의 날짜별 중복 구분·부칙 날짜 필터·날짜가 남는 안내와 I03의 원문 범위·숫자 경계·성공 제외를 모두 보존한 통합 결과는 아직 실행하지 않았다. 두 독립 PR의 통과 결과가 통합 검증을 대신하지 않는다.

## 검토 기준에 따른 설명 보완

- B2/B6: I02에 날짜 공백, 꺾쇠, 공포번호가 섞여 해석 불가인 표기 테스트를 더했다. 해당 개정일의 부칙 조문 블록을 찾지 못한 경우와, 그 날짜 부칙은 있으나 조문이 없는 경우의 안내를 구분한다. 날짜는 부칙 머리의 개정일이며 시행일 판정을 하지 않는다.
- D3/D5: `제1234조`는 main에서 `RULE_EXISTS·verified 1`, I03에서 `UNSUPPORTED_CITATION·verified 0`임을 실행 확인했다. `「취업규칙」에 따라`는 두 버전 모두 `RULE_EXISTS·verified 1`이다. 두 입력을 회귀 테스트에 명시했다.
- D4: 호·목은 미지원 확인필요다. 현재 범위(`제3조 내지 제5조`, `제3조~제5조`)와 나열(`제3조·제4조`)은 명시된 조문을 개별 인용으로 추출한다. 범위 사이의 생략된 조문은 검증하지 않는다. 이를 도구 설명과 구조화 계약에 명시하며 `verified`를 범위 전체 확인으로 해석하면 안 된다.
- E4~E9: summary의 기존 6개 키는 유지한다. 새 확인필요 상태는 `exists`에 넣지 않는다. 출력 머리줄도 같은 summary 값을 사용한다. 도구 출력 스키마는 `data` 객체를 허용하며 상태 enum을 제한하지 않는다. `src/finance-desk.js`의 소비자는 상태 문자열이 아니라 `notFound`·`needsReview`·`floating`·`truncated`로 불완전 여부를 판정하므로 두 새 상태의 확인필요 집계를 그대로 받는다.
- F1~F5: 각 독립 브랜치의 날짜 처리와 확인필요가 통과가 아님을 도구 설명에 적었다. I03에는 미지원 상세 표기와 범위 사이 조문 미검증도 적었다.

변경한 것은 인용 검증·안내·회귀 테스트다. 검색 순위·발췌·의미검색·패키지 버전·캐시 형식은 바꾸지 않았다. 실제 연결 MCP, 배포 환경, 법적 적용성, 두 PR을 합친 결과는 이번 독립 PR 실행으로 확인하지 않았다.
