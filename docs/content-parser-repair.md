# 번호 없는 조문 본문 누락 수정

공식 HTML의 `article_none`은 제목 다음에 나오는 번호 없는 조문 본문입니다. 기존 파서는 `article`, `none`, `hang`, `ho`, `mok` 등만 읽어 `article_none` 및 항·호의 계속문장을 버렸습니다. 원본에 본문이 있어도 전문 색인에는 제목만 남을 수 있었습니다.

파서는 `article_none`, `hang_none`, `ho_none`, `mok_none`, `dann`, `dann_none`, `addendacontent_none`을 문서 순서대로 보존합니다. 화면 조작 버튼·컨테이너는 본문에 넣지 않습니다. 부칙 경계와 삭제 표시를 유지하며, 실제 빈 조문에 내용을 만들어 넣지 않습니다.

## 기존 캐시 이행

본문 캐시는 `content-v4`를 사용합니다. 기존 `content-v3` 파일은 수정하거나 삭제하지 않습니다. 전문 색인에는 `contentVersion: 4`를 기록하며, 버전이 없거나 다른 색인은 검색에 사용하지 않습니다. 이때 기존 원문 사이트 검색 경로로 폴백합니다.

업데이트 후 반드시 다음 순서로 색인을 다시 만듭니다. 원본 캐시를 보존해 비교하려면 별도 `XDG_CACHE_HOME`에서 실행하세요.

```sh
dongguk-rule-mcp --build-index
# 의미검색을 사용하는 설치만 실행
dongguk-rule-mcp --build-semantic-index
```

`--build-index`는 같은 연혁이라도 이전 파서로 만든 본문을 재사용하지 않습니다. 규정 수 급감 방지는 이전 색인과 비교해 계속 적용합니다. 한 번 새 파서로 만든 뒤에는 동일 연혁을 재사용합니다. 의미 벡터는 수정된 본문 해시에 따라 다시 만들고, 동일한 본문의 벡터는 재사용할 수 있습니다.

이 수정은 검색 순위 규칙·사전·가중치를 바꾸지 않습니다. 본문이 복구되면 검색 입력이 달라져 후보 순위와 발췌가 달라질 수 있으므로, 같은 규정·연혁의 전후 캐시로 평가해야 합니다.

## 검증

`test/test-content-parser.js`는 실제 HTML에서 관찰한 클래스 구조에 합성 문장을 넣어, 본문과 계속문장의 순서·중복 방지·부칙 경계·삭제 조문·캐시 버전 이행·옛 색인 재사용 방지를 검사합니다. 전체 `npm test`에도 포함됩니다.

공개 문항 평가는 `scripts/d1-baseline.js --help`를 참고합니다. train/dev만 사용하고 엄격 정답률, 정답 규정 상위 3위 포함률, 그 조건에서 정답 조문 포함률을 구분합니다. 오프라인 캐시 측정의 지연은 실제 원문 서버 응답 시간을 포함하지 않습니다.
