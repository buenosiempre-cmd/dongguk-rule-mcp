# 발췌 선택 견고성 실험

`DONGGUK_MCP_EXCERPT`는 `lookup_dongguk_rule`의 발췌 선택만 바꾸는 opt-in 실험이다. 미설정·`legacy`·알 수 없는 값은 기존 동작을 유지한다. 규정 후보 순위와 기본 환경 변수는 바꾸지 않는다.

| 값 | 점수 단위 | 발췌 낱말 / 우선 조문 |
|---|---|---|
| `legacy` (기본) | 기존 문단 | 기존 확장 낱말·우선 조문 |
| `article` | 조문 | 기존 확장 낱말·우선 조문 |
| `literal` | 기존 문단 | 질문 낱말·명시 입력 / 자동 우선 조문 제외 |
| `article-literal` | 조문 | 질문 낱말·명시 입력 / 자동 우선 조문 제외 |

`article` 계열은 빈 줄 수와 관계없이 한 조문을 한 순위 자리로 센다. 점수 계산용 본문에서 산문 줄바꿈을 평탄화해 줄 맨 앞 상호 인용이 표제 가산을 받는 현상을 막는다. 응답에는 원문을 그대로 보존한다. 장·부칙·별표 경계는 넘지 않으며, 별표는 기존처럼 본체와 주석을 함께 취급한다. 동점은 문서 순서를 유지한다. `max_sections`·`max_chars` 제한 및 생략 표시도 유지한다. 이 방식은 새 의미 점수나 정답 조문 보장 기능이 아니다.

`literal` 계열은 기존 `queryContentTokens`의 질문 낱말(최대 4개), 명시한 조문·별표, 사용자가 준 `keywords`를 사용한다. 명시한 `terms`가 있으면 그 값을 그대로 사용한다. 사전의 동의어·관련어 확장 결과(`searchTerms`)는 발췌에 전달하지 않는다. 기존 조사 처리와 사전의 명사 보호(`knownTerm`)는 유지하므로 토크나이저까지 사전에서 독립한 실험은 아니다.

자동 `priorityArticles`는 어휘와 의미검색의 결과가 합쳐진 값이라 `literal` 계열에서는 모두 제외한다. 따라서 이 조건은 사전 확장어 차단뿐 아니라 의미검색 우선 조문도 제거한다. 효과를 사전 분리만의 효과로 해석하면 안 된다. 규정 선택 단계의 의미검색과 순위는 유지한다.

실험 응답은 `data.query.excerptPolicy`에 적용 모드를 기록한다. 기본 응답에는 이 필드를 추가하지 않는다. 환경 변수는 요청마다 읽는다.

## 변경 경계

- 새 `src/excerpt-policy.js`: 모드·조문 단위 분리·점수용 산문 정규화·입력 선택.
- `src/lookup.js`: opt-in 블록 생성 및 점수 입력, 조문 안 표의 앞뒤 문맥이 다른 조문을 끌어오지 않도록 처리.
- `src/index.js`: 발췌 직전 낱말·우선 조문·옵션 전달과 실험 모드 기록만 변경.
- `src/corpus.js`, `src/fusion.js`, 규정 순위 함수, 사전은 수정하지 않음.

## 검증과 해석

`node test/test-excerpt-policy.js`와 `node test/test-excerpt-policy-mcp.js`는 합성 규정만 사용한다. 문단 분할, 동일 조문 슬롯 중복, 상호 인용 줄바꿈, 부칙·별표, 명시 조건, 길이 제한, 실제 MCP 후보 순위 불변, 기본값 복원 등을 검증한다.

실제 공개 문항 평가는 전체 원문 구조 캐시의 공통 기준 공지 뒤에 시행한다. 동일 corpus·semantic·코드에서 HTML만/HWP 포함을 분리하고, 각 모드의 strict·정답 규정 top3·조건부 정답 조문 포함률과 새로 틀린 문항을 전부 보고한다. 원문 내용 자체가 다른 경우와 같은 내용의 문단 경계만 다른 경우도 구분한다. 보류셋은 사용하지 않는다. 이 문서 작성 시점에는 실제 문항 개선을 주장하지 않는다.
