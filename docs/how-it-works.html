3규정 원문 수집과 색인

원문은 질문할 때마다 공식 사이트에서 읽고, 자주 쓰는 결과는 디스크 캐시에 잠시 둡니다. 규정명이 없는 질문을 위해 전체 공개 규정의 조문 단위 색인을 따로 만듭니다.

① 규정 목록

전체 현행 규정 목록을 한 번에 받아 옴 (캐시 10분)

② 연혁 → 개정본

규정별 개정 이력에서 최신(또는 기준일) 개정본 HISTORY_ID 선택 (캐시 10분)

③ 원문 읽기

통합 조회(lookup_dongguk_rule) 등은 원문 HWP를 먼저 풀어 조문·별표·표 셀까지 읽고, 실패하면 HTML 본문으로 대체 (부분 결과로 표시)

④ 조문 단위 정리

제○조·부칙·별표 단위로 나눠 마크다운으로 정리 (본문 캐시 30일, 개정본별)

전문 색인 (자연어 질문용)

  • 운영자가 --build-index로 만들거나, HTTP 서버가 DONGGUK_MCP_INDEX_REFRESH_HOURS 주기로 갱신
  • 전체 공개 규정의 HTML 본문을 조문 단위로 저장. 개정본이 같은 규정은 다시 읽지 않고 재사용
  • 목록이 이전 색인보다 20% 넘게 줄면 갱신을 멈춤. 읽기 실패가 5%를 넘으면 색인은 저장하되 실패(ok:false)로 보고
  • 8일이 지난 색인은 “오래됨”으로 표시하고, 쓰더라도 현행 개정본은 다시 확인
  • 색인은 후보 찾기에만 씀. 답에 쓰는 본문은 현행 목록·연혁으로 개정본을 다시 확인한 뒤 원문(개정본별 캐시 포함)에서 읽음

4자연어 조회 흐름 (lookup_dongguk_rule)

대부분의 질문이 이 도구에서 시작합니다. 규정 찾기 → 적용 범위 맞추기 → 개정본 고르기 → 조문 발췌 순서입니다.

0단계검색어 다듬기
질문에 규정명이 있으면(“여비규정에서 …”, 띄어 쓴 현행 규정 제목 포함) 규정명과 나머지 핵심어로 나눕니다. 규정명은 그대로 두고, 별칭(전결규정→위임전결규정, 취규→취업규칙), 가운뎃점 표기 변형, 띄어쓰기 압축, ‘규정’ 접미어 생략형을 함께 만듭니다.
1단계규정 선택
규정 제목이 정확히 맞으면제목 검색
공식 사이트 규정명 검색으로 바로 그 규정을 확정 (exact_title)
제목이 없는 여러 단어 질문이면핵심어 색인
조사·어미를 떼고 핵심어를 뽑아 규정 용어로 넓혀 찾음(출장비→여비, 해외출장→국외출장, 안식년→연구년). 어느 규정에도 없는 복합어는 짧은 형태로 다시 찾음
색인·제목 검색 모두 후보가 없으면공식 전문검색
핵심어로 사이트 본문 검색, 가장 긴 단어·끝 단어를 빼 가며 최대 4번(약 35초 예산)
2단계적용 범위
질문 속 범위어(서울캠퍼스 · WISE(경주)캠퍼스 · 산학협력단 · 의학계열)나 campus 인자(seoul·wise)가 있으면 같은 규정의 해당 판을 고릅니다. 범위가 없거나 둘 이상이면 판을 합치지 않고 후보로 함께 보여 줍니다. 범위어는 “어느 판인지”를 고를 뿐, 교원·직원·학생 적용 여부까지 판정하지 않습니다.
3단계후보 정리
한 규정이 뚜렷하게 앞서면그 규정 1곳의 미리보기 (적용 규정 확정은 아님)
비슷한 점수가 여럿이면가까운 규정 최대 3곳의 맞는 조문을 나란히 미리보기
제목 검색에서 여러 후보가 나오면AMBIGUOUS_RULE로 후보 목록을 주고 law_id로 다시 고르게 함
4단계조문 선택
최신 개정본의 원문 HWP를 읽고(과거 날짜 기준 개정본은 applicable_rule이 찾음), 핵심어·“제○조”·“별표 ○” 지정과 맞는 블록을 관련도 순으로 고릅니다. 기본 최대 4개 블록 · 12,000자(여러 규정을 함께 보이면 3개 · 6,000자).

6타대학 비교 (compare_university_rules)

동국대는 자동으로 들어가고, 비교할 대학을 1~5곳 고릅니다. 각 대학의 공개 규정만 읽어 같은 주제의 조문을 나란히 보여 줍니다.

① 주제

주제어(100자 이내)를 넓힘. 등록된 사안 틀 7개: 겸직 · 여비 · 연구비 · 등록금 반환 · 퇴직급여 · 근로장학 · 장학금

② 대학별 차례로 조회

동국 → 선택한 대학 순서대로. 대학당 규정 최대 5개, 요청 8초 제한·0.5초 간격, 전체 60초

③ 조문 고르기

제목·조문 일치로 대학마다 1~5개(기본 3개). 사안 틀이 있으면 다른 사안의 규정·조문은 빼고 이유를 남김

④ 나란히 표

짧은 발췌 표 + 대학별 조문 본문. 대학마다 retrieved / partial / no_match_in_scope / unavailable (모르는 대학 키는 unsupported)

서울대는 국가법령정보센터 학칙 자료를 운영자 법제처 키(DONGGUK_LAWGO_OC)로 읽습니다. 키가 없으면 그 열에만 설정 안내가 붙습니다.

비교 결과를 읽는 법

  • 행 순서나 조문 번호는 대학 간 법적 대응·동등성을 뜻하지 않습니다
  • 로그인해야 보이는 규정은 읽지 않습니다. 조회 범위에서 못 찾은 것은 비공개나 부존재의 증거가 아닙니다
  • 조문만 비교합니다. 별표·표·그림·서식은 각 대학 원문에서 확인
  • 기본으로 켜져 있고, 운영자가 DONGGUK_UNIVERSITY_COMPARISON_ENABLED=0으로 끌 수 있음
  • 공통 조회 클라이언트의 응답 캐시는 기본 10분. 운영자는 university-watch로 대학별 대표 여비 규정의 개정을 주간 점검할 수 있음

7상위·관계법령 조회 (get_rule_upper_laws · get_rule_references)

규정이 이름을 들어 인용한 법령을 뽑아, 법령 서버의 현행 법령 목록과 조문에 대조합니다. 결과는 “다시 볼 곳” 신호이며, 규정이 법령에 어긋난다거나 사안에 적용된다는 판정이 아닙니다.

재시도와 이어 보기

  • 법령 서버가 429(한도 초과)를 주면 최대 2번, 한 번에 최대 5초 기다렸다 다시 시도
  • 그래도 막히면 LEGAL_UPSTREAM_RATE_LIMITED로 알림
  • 법령이 많으면 page.nextOffset → law_offset으로 나머지 확인
  • get_service_info에서 호출·캐시 적중·한도 초과·재시도 횟수 확인
조회 예 (2026-11-26): 「취업규칙」 제17조가 인용한 「사립학교법」 제70조의4를 현행 법령 목록과 조문 본문으로 대조해 찾아옵니다. v0.15.9에서 본문 첫 줄이 다른 조문 번호로 시작하는 경우를 조문 머리로 잘못 읽던 문제를 고쳤습니다.

8안전장치

민감정보 검사

질문·검색어·인용 검증 문장·주제어에 아래 형식이 보이면 도구를 실행하지 않고 SENSITIVE_INPUT으로 거절합니다. 일부 형식만 알아보므로, 처음부터 넣지 않는 것이 원칙입니다.

  • 휴대전화 번호, 이메일 주소
  • 계좌·카드·주민등록번호, 13~19자리 숫자
  • “비밀번호=…”, “api_key: …”처럼 이름과 함께 적은 인증값

요청 한도

  • 토큰 없는 요청: 접속 IP마다 1분 60회 · 하루 1,000회 (기본값, 운영자가 조정 가능)
  • 넘으면 HTTP 429와 Retry-After
  • 터널 뒤에서는 loopback에서 온 CF-Connecting-IP만 신뢰
  • 동시 처리 8건, 대기 32건, 넘치면 429
  • /health·/ready·안내 페이지는 한도 제외. /ready는 요청 수용 상태만 뜻하고 원문·법령 서버 정상 여부는 아님

토큰

  • Bearer 토큰. 구성원 등록 파일에는 SHA-256 해시만 두고 고정 시간 비교 (운영자용 단일 토큰 설정도 지원)
  • 토큰마다 허용 경로·만료일·사용 여부, 관리자만 /status
  • 토큰이 없으면 외부에서 바로 닿는 주소(loopback 외)로는 서버가 뜨지 않음
  • 허용 안 된 Origin, 일괄(batch) 요청 거절

인용 원칙

  • 규정 조회·조문·전문·상위/인용 법령 결과에는 LAW_ID·HISTORY_ID·개정일·원문 링크 (본문 일괄 검색 search_rule_deep은 사이트 주소만)
  • 잘림·대체·미확인은 partial과 사유 코드로 표시
  • 개정일 ≠ 시행일. 부칙·경과조치는 따로 확인하라고 안내
  • retrieved는 추출 범위가 빠짐없다는 뜻일 뿐 적용성 보장이 아님. 검색 0건·“인용 존재”도 검증 통과가 아님
  • 별도 첨부 자동 다운로드와 OCR은 하지 않음

읽기 전용 · 공개 자료만

  • 신고·지급·결재·발송 같은 쓰기 동작 없음
  • 공개 경로는 로그인 쿠키·내부 자료팩을 쓰지 않음
  • 공개 캐시와 쿠키 사용 캐시는 폴더를 분리

사용 로그(선택)

운영자가 켠 경우에만 시각·소요 시간·도구 구분(비교/기타)·HTTP·처리 상태·대학별 결과와 실패 코드만 남깁니다. 입력 인자·IP·토큰·규정 제목·본문은 남기지 않습니다.
