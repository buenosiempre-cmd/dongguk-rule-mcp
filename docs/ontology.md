# 온톨로지 모듈 연결 계약

온톨로지는 검색용 분류 정보입니다. 적용 여부나 법적 우열을 판정하지 않고, 점수를 계산하거나 후보를 추가하지 않습니다. `corpus.js`·`index.js`와 실제 결합 호출부는 이 작업에서 변경하지 않았습니다. t110의 `fusion.js`에서 아래 선택 신호를 연결합니다.

```js
const { createFacetSignal } = require('./ontology');
const facets = createFacetSignal({ corpus, query, keywords });
// corpus가 없거나 rules 배열이 없으면 null
// facets.question: 질문의 대상·범위·개념
// facets.ruleOf(lawId): 규정 분류. 모르는 ID는 null
// facets.matchOf(lawId): { subject, campus, institution }
// 각 값: 'match' | 'mismatch' | 'unknown'
// facets.status: 'packaged' | 'fallback'
rankRules({ corpus, query, keywords, lexical, semantic, graph, facets, method });
```

`unknown`은 일치도 불일치도 아닙니다. 결합 계층에서 중립으로 취급하고, 분류만으로 단독 확정하지 않아야 합니다. 가중치·점수 결합·실제 조회 연결은 t110이 맡습니다. 과거 기준일·조문/별표 명시·쿠키 요청에서 새 신호를 사용하지 않는 책임도 호출부에 있습니다.

## 자료와 기존 사전

- `src/data/ontology.json`: 기존 사전에서 그대로 이전한 204개 동의어 묶음, 대상 5종(직원·교원·학생·강사·조교), 범위 6종, 개념 분류 5종(보수·수당·여비·휴학·복학), 규정 종류와 편제 분류.
- `src/aliases.js`: 이 자료로 기존 `CONCEPT_GROUPS`, 대상·범위 함수를 구성합니다. 동의어 방향·순서·기존 반환 계약을 유지합니다. 새 분류용 서울 범위는 기존 `questionScope` 반환 객체에는 추가하지 않습니다.
- `src/ontology-defaults.js`: 자료 누락·JSON/스키마 오류 시 쓰는 내장 스냅샷. 기본 자료와 일치하는지 테스트합니다. 자료 변경 시 두 파일을 함께 갱신해야 합니다.
- 기존 문항 표현이나 LAW_ID를 추가 매핑하지 않았습니다. 기존 동의어를 늘리지 않고 분류 표제를 붙였습니다. v4~v6와 보류셋은 사용하지 않았습니다.

기존 `questionSubject`는 대상이 복수면 null을 내는 계약을 유지합니다. 새 `questionFacets`는 복수 대상을 보존하고 불명확함을 표시합니다. `교원` 대상 규정은 `강사` 질문을 포함할 수 있으나 그 반대는 자동으로 인정하지 않습니다.

## 질문·규정 분류

`questionFacets(query, keywords)`와 `ruleFacets(rule)`은 다음 모양의 불변 객체를 반환합니다.

```js
{
  subjects: ['직원'],
  scopes: { campus: ['wise'], institution: [] },
  concepts: ['여비'],
  evidence: [{ dimension: 'subject', value: '직원', source: 'title' }],
  ambiguities: [],
  // 규정에만:
  kind: '내규',
  articleCount: 3
}
```

- 질문의 캠퍼스·기관은 `query`에서만 읽습니다. `keywords`의 기관명으로 범위를 바꾸지 않습니다. 대상은 질문에 없을 때에만 keywords를 보조로 사용합니다.
- `서울 출장` 같은 지명만으로 서울캠퍼스라고 판단하지 않습니다. 서울캠퍼스·서울본교처럼 범위가 명시돼야 합니다. 범위 미지정은 서울판을 뜻하지 않습니다.
- 규정 제목과 본칙의 적용범위·적용대상·적용 조문을 읽습니다. 일반 본문 인용과 부칙은 대상 판단 근거로 쓰지 않습니다.
- 제목이 넓고 적용대상이 좁으면 공통 대상만 남깁니다. 서로 충돌하면 해당 분류를 비우고 `CONFLICT_*`를 표시합니다. 제외·준용 등 조건이 있으면 범위를 확정하지 않고 `QUALIFIED_APPLICATION`으로 남깁니다.
- 편제 `8-`은 산학협력단 규정집의 약한 근거로 `evidence`에 기록합니다. 코드만으로 기관 적용이나 서울캠퍼스를 확정하지 않습니다.
- `evidence.source`는 `query`, `keywords`, `title`, `application`, `code`입니다. 적용범위 조문에는 원래 `blockIndex`, 코드 추정에는 `inferred: true`가 있습니다.
- `articleCount`는 부칙을 제외한 문자열 본문 블록 수입니다. 벡터 조각 수나 별표 수를 세지 않습니다.
- corpus 객체를 키로 한 WeakMap 캐시를 사용합니다. 색인이 바뀌면 새 corpus 객체를 전달해야 합니다. 같은 객체의 내용을 나중에 바꾸는 방식은 지원하지 않습니다.

## 순위 결합에서 쓰는 추가 분류 (t110, fusion 연결)

`docs/ranking.md`의 `hybrid` 방식이 쓰는 항목입니다. 위의 `questionFacets`·`ruleFacets`·`matchFacets` 출력과 기존 사전 함수 출력은 바꾸지 않았습니다(출력 서명 테스트 그대로 통과).

- `placeRequest(query, campus)` → `{campuses, institutions, specified, ambiguous}`: 순위가 읽는 장소. 캠퍼스와, 전교 규정의 판을 따로 가진 기관(`scopes[].edition`: 산학협력단·의학계열)만 봅니다. 의학계열은 `scopes[].place`의 말(의대·의과대학·의학과·의예과·의전원·병원·의료원·임상교원)로만 읽고, 분야 이름일 뿐인 "의학"(불교의학연구소)은 읽지 않습니다. 대학원은 판을 고르거나 버리는 근거로 쓰지 않습니다(대학원생 질문의 답이 전교 규정에 있는 경우가 많음).
- `placeAgreement(title, request)` → 정수: 규정이 물은 곳의 것이면 양수, 묻지 않은 곳의 것이면 음수, 전교 규정이거나 장소를 묻지 않았으면 0. 규정의 장소는 제목으로만 읽습니다. 본칙 앞 조문(목적·명칭 및 소재·적용범위)에서 캠퍼스를 읽는 방안은 시험했으나 채택하지 않았습니다(아래).
- `bodySubject(rule)`·`ruleFacets(rule).bodySubject`: 제목과 적용범위 조문이 대상을 말하지 않는 규정에서, 본칙이 거듭 부르는 직군. 한 직군이 전체 직군 언급의 80% 이상이고 조문당 0.8회 이상, 합계 10회 이상일 때만 값이 있습니다(취업규칙 → 직원). `evidence`에 `source: 'body', inferred: true`로 남기며 적용 판단이 아닙니다. 기준값은 `bodySubject` 자료에 있습니다.
- `createFacetSignal(...).covers(넓은 대상, 좁은 대상)`: 교원 규정이 강사 질문을 포함하는지.

### 일상어 이름 사전 (`labels`)

기존 동의어 204묶음(`concepts`)과 따로 둔 29묶음입니다. 항목은 대상·기관·사물의 이름이고, 질문을 규정이나 조문에 잇는 항목은 없습니다. 싣는 기준은 두 가지입니다.

1. **일상어는 규정집이 거의 쓰지 않는 말만**(그 말이 나오는 규정이 513개의 1% 이하, 즉 5개 이하). 규정이 이미 쓰는 말(특허 20건, 계약직 26건, 상담센터 13건 등)은 그 말만으로 규정을 찾으므로 싣지 않습니다. 실으면 같은 규정 안에서 다른 조문이 발췌로 뽑히는 잡음이 생깁니다(D1 색인에서 "특허 → 지식재산권" 한 묶음이 공개 문항 R03의 발췌 조문을 바꿔 확인).
2. **규정 용어는 규정 본문에 나오는 말만.** 0건인 용어는 뺐습니다. 기존 묶음에 이미 있는 낱말도 넣지 않았습니다(테스트로 고정).

### 알려진 한계와 시험: 규정의 캠퍼스를 제목으로만 읽음

`placeAgreement`는 규정 제목에 캠퍼스가 있을 때만 그 규정을 캠퍼스 규정으로 봅니다. 공통 기준 색인(corpus `830b6996…`)에서 제목에 캠퍼스가 없는 규정 396개 가운데

- 제1조에 서울캠퍼스만 나오는 규정이 134개입니다. 24개는 같은 계열에 WISE판이 있어 WISE 질문에서 판 고르기로 빠지지만, **110개는 WISE판이 없어 전교 규정처럼 후보에 남습니다.** 대부분 연구소·연구원·센터·학술원·교육원의 "서울캠퍼스에 둔다"이고, 그 밖의 규정이 27개입니다(법인카드 관리 및 사용에 관한 규정, 안전보건관리규정, 미화직 임용에 관한 내규, 기록물관리에 관한 규정 등). 이런 규정은 `hybrid`에서 WISE 질문의 답으로 나올 수 있습니다.
- 제1조에 WISE·경주캠퍼스만 나오는 규정이 27개입니다(연구소, 금장생활관규정, 국제불교영어학과 학사시행세칙 등). 제목에 캠퍼스가 없어 WISE 질문에서 가점을 받지 못합니다.

본칙 앞 조문에서 캠퍼스를 읽어 순위 결합에 넘기는 방식을 실험 브랜치에서 표준 하네스로 시험했습니다(그 연결 훅은 이 코드에 없습니다)(제1조만 읽는 방식과, 앞 세 조문의 목적·적용범위·명칭 및 소재를 읽는 방식 둘 다). `hybrid` 대비 공개 251·probe9·dev_open·scope12v2에서 달라진 문항이 없고, 개발 문항 하나(WISE 직원 징계 종류 → 취업규칙)가 새로 틀렸습니다. 제1조에 WISE캠퍼스가 적힌 국제불교영어학과 학사시행세칙이 WISE 규정으로 읽혀 가점을 받아, 전교 규정인 취업규칙을 상위 3 밖으로 밀어냈기 때문입니다. 지금 있는 문항으로는 이득을 보이지 못해 순위에 넣지 않았고, 훅만 남겼습니다. 다만 위 한계는 실제이므로 문항이 갖춰지면 다시 볼 일입니다.
