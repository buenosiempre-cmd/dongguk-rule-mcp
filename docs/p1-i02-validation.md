# 날짜 부칙 인용 검증

날짜 부칙을 본칙으로 축소하지 않고, 본문 파서와 같은 `normalizeArticleSelector`로 해석해 해당 부칙을 대조한다. 일반 문장의 부칙 낱말과 조문 선택자는 구분한다.

- `부칙(2099.1.1.) 제1조`: 날짜가 확인되는 다른 부칙만 있으면 `NOT_FOUND`다.
- 일치하는 날짜를 찾지 못했고 원문에 날짜 미상 부칙이 있으면 `ARTICLE_SELECTOR_UNVERIFIED`다.
- 괄호·날짜를 해석하지 못한 경우도 `ARTICLE_SELECTOR_UNVERIFIED`다.
- `부칙에 따라 시행하며, 제3조를 준용한다`: 본칙 제3조를 검증한다.
- 정상 날짜, 날짜 없는 단일 부칙, 가지조문, 조문 제목·항 검증을 유지한다.

상태·집계 의미는 [날짜 부칙 인용 상태 계약](citation-integration-order.md)을 따른다. 실행 결과와 다른 변경의 반영 순서는 PR 본문에서 관리한다.

## 재현

```sh
npm test
node scripts/reproduce-citations.cjs citation-repros.json
```

테스트와 재현 스크립트는 합성 본문을 사용하며 공식 규정에 대한 법적 판단이 아니다. 검색 순위·발췌·패키지 버전·캐시 형식은 바꾸지 않는다.

최신 테스트 수치와 검증한 commit은 PR 본문에서 관리한다.

`부칙(날짜)의 제1조`와 `부칙(날짜) 중 제1조`도 같은 날짜 선택자로 검증한다. 일반 문장의 `부칙의 취지`·`부칙 중 적용대상`과 구분한다.

날짜가 붙은 부칙 선택자를 먼저 보존한다. 같은 문장의 바로 다음 조문과 연결을 해석하지 못하면 (`에서`, `중의`, `에 따른`, `가운데` 등) `ARTICLE_SELECTOR_UNVERIFIED`로 남기며 본칙으로 후퇴하지 않는다. 날짜 없는 일반 서술문, 다음 문장, 다른 규정명에는 이 보존 규칙을 적용하지 않는다.

남은 한계: `제1조의 2가지 목적` 같은 수량 표현을 가지조문으로 오인하는 기존 동작은 별도 개선 대상이다.
