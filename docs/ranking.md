# 규정 후보 순위 결합과 범위 판별

자연어 질문의 규정 후보 순서와 캠퍼스·기관 판 고르기는 `src/fusion.js` 한 곳에서 정합니다. 낱말 색인(`corpus.js`)이 후보와 점수를 내고(의미검색이 켜져 있으면 그 가산 포함), 이 모듈은 질문이 말한 캠퍼스·기관·대상을 읽어 순서를 정합니다. 후보를 새로 만들지 않습니다.

## 설정 두 가지 (둘 다 기본 켜짐)

| 환경변수 | 값 | 동작 |
|---|---|---|
| `DONGGUK_MCP_RANKING` | `hybrid`(기본), `legacy`(끄기) | 규정 후보의 순서와 판 고르기. 모르는 값은 `hybrid`로 읽습니다 |
| `DONGGUK_MCP_LABELS` | 켜짐(기본), `0`·`off`·`false`·`no`로 끄기 | 일상어 이름 사전 29묶음과 낱말 처리. 내용은 `docs/ontology.md` |

- `DONGGUK_MCP_RANKING=legacy`, `DONGGUK_MCP_LABELS=0`으로 둘 다 끄면 이 모듈을 넣기 전과 같은 응답을 냅니다(조회 시각 말고는 필드까지 같음).
- 켠 때만 응답의 `search.ranking: "hybrid"`, `search.labels: true`가 나옵니다. 켜졌는지는 이 두 값으로 확인합니다.
- 서로 독립입니다. 하나만 켜거나 끌 수 있고, 끄면 다음 조회부터 이전 동작입니다(색인·벡터를 다시 만들지 않음). 프로세스를 다시 띄워야 반영됩니다.
- 의미검색(`DONGGUK_MCP_SEMANTIC`)과도 독립입니다. 런타임이 없는 서버에서도 동작합니다.

## `legacy`와 `hybrid`

| 값 | 동작 |
|---|---|
| `legacy` | 낱말 점수(의미 순위 가산 포함) 순서. 질문이 말한 캠퍼스·기관의 판이 하나라도 있으면 그 판의 규정만 남기고 나머지를 버림 |
| `hybrid` | 점수는 같고, 캠퍼스·기관을 온톨로지로 읽음. 물은 곳의 규정은 1.5배, 다른 곳의 규정은 0.6배, 전교 규정은 그대로 후보로 남김. 본문이 다른 직군의 규정은 0.8배 |

`hybrid`가 `legacy`와 다른 점은 네 가지입니다.

1. **전교 규정을 버리지 않습니다.** "경주캠퍼스 직원 병가"에 WISE판이 없는 취업규칙이 후보로 남습니다. `legacy`는 제목에 WISE가 든 규정이 하나라도 걸리면 나머지를 모두 버립니다.
2. **판은 캠퍼스와 기관이 모두 맞아야 고릅니다.** 캠퍼스만 물었을 때 "WISE캠퍼스 산학협력단 취업규칙"이 취업규칙을 대신하지 않습니다.
3. **다른 캠퍼스·다른 기관의 규정은 나머지가 맞아도 불일치입니다.** "서울캠퍼스 산학협력단" 질문에 "WISE캠퍼스 산학협력단 취업규칙"은 중립이 아니라 다른 곳의 규정입니다. 같은 계열에 맞는 판이나 전교 규정이 있으면 빠지고, 없으면 0.6배로 남습니다.
4. **기관은 그 기관을 가리키는 말로만 읽습니다.** 의대·의학과·병원은 의학계열이고, 불교의학연구소·의학연구소는 연구소 이름입니다(`src/data/ontology.json`의 `scopes[].place`).

질문이 캠퍼스·기관을 말하지 않으면 `hybrid`가 `legacy`와 달라지는 곳은 본문 직군 가중(0.8배)과, 판이 여럿인 계열의 처리뿐입니다.

한 규정만 보여 주는 판정은 방식과 관계없이 낱말 점수로 합니다(1위가 나머지보다 1.3배 이상). `legacy`는 여기에 "1위만 범위가 맞고 2위는 아닌 경우"를 더 봅니다. `hybrid`는 다른 곳의 규정이 1위면 단독으로 확정하지 않습니다.

## 알려진 한계

- **규정의 캠퍼스는 제목으로만 읽습니다.** 제목에 캠퍼스가 없지만 제1조가 서울캠퍼스 한정인 규정(WISE판이 없는 것 110개)은 전교 규정처럼 다뤄져 WISE 질문의 후보로 남습니다. `legacy`는 이런 규정과 진짜 전교 규정을 함께 버렸습니다. 수와 시험 결과는 `docs/ontology.md`.
- **1위 정확도.** 물은 캠퍼스가 제목에 든 규정은 주제가 덜 맞아도 1.5배 가점으로 전교 규정보다 앞설 수 있습니다. 정답 규정은 상위 3 안에 남지만 1위가 아닐 수 있습니다.
- **가중값(1.5·0.6·0.8)은 개발 문항에서 고른 값입니다.** 1.2~2, 0.4~0.8 범위에서 개발 문항 결과가 같았습니다.

## 호출 형태

```js
const { rankRules } = require('./fusion');
rankRules({
  candidates,   // 낱말 색인이 찾은 규정: { lawId, title, family, edition, score, ... }
  scope,        // lookup.requestedRuleScope(질문, campus) — legacy가 쓰는 범위
  query, campus,// 질문과 도구의 campus 인수 — hybrid가 온톨로지로 장소를 읽음
  facets,       // ontology.createFacetSignal({corpus, query}) 또는 null
  method,       // 생략하면 DONGGUK_MCP_RANKING
}) // → { method: 실제 쓴 방식, ranked: [{ ...후보, scopeMatch, scopeAmbiguous, editions }] }
```

- `index.js`·`corpus.js`의 순위 코드는 이 모듈을 통해서만 바꿉니다.
- 실험에서 쓰던 방식(`rrf`, `jev`)과 훅(그래프 관계, 확률, 호출부 장소 판독), 측정용 스위치는 이 모듈에 없습니다. 그 이름을 넘겨도 읽지 않습니다(`test/test-fusion.js`에서 확인).

빈 값·미지정·알 수 없는 값은 기본 켜짐으로 읽습니다. 기존 설정의 변수를 지우는 것은 끄기가 아닙니다. 의미검색의 자동 사용 조건과는 독립입니다.
