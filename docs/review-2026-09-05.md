# 동국 규정 MCP 분석·개선 결과

검토일: 2026-09-05

대상: 로컬 main의 `447b095`(v0.6.0), 개선 브랜치 `agent/reliability-review-2026-09-05`.
운영 서버가 실행 중인 경로·커밋은 확인하지 않았다. 이 문서의 완료는 로컬 코드와 검증 완료를 뜻한다.

## 판단

검색, HWP 표 추출, 구조화 응답, stdio·HTTP 테스트가 이미 갖춰져 있다.
새 도구를 늘리기 전에 최신본 선택과 비교 결과의 신뢰성을 보강하는 것이 우선이다.
기존 테스트 160개가 통과해도 실제 핸들러의 오래된 캐시·잘못된 ID 조합은 검증되지 않았다.

기존 도구 이름과 버전은 유지했다. createServer를 가져올 때 서버가 자동 시작되지 않도록 진입점을 분리하고, 실제 MCP 핸들러를 호출하는 회귀 테스트를 추가했다.

## 검증

- 변경 전: npm test 7개 스위트 160개 통과.
- 변경 후: npm test 8개 스위트 182개 통과. 신규 22개는 임시 캐시와 차단된 네트워크 환경에서 실제 MCP 핸들러를 검증한다.
- 실사이트 스모크: 여비 검색·본문·연혁·HWP 다운로드 및 파싱 14개 통과. 캠퍼스 코드는 이 검사로 확정되지 않는다.
- 변경 후 실제 MCP 호출: 캐시 비활성화, 로그인 쿠키 없이 여비규정 조회 성공. LAW_ID 184 / HISTORY_ID 3350 / 개정일 2025.04.29, HWP에서 관련 내용 1,144자 추출. 반환 연혁 첫 항목과 개정본 일치 확인.
- 변경 후 실제 MCP 비교: 여비규정 최신·직전 개정본 비교 성공. HTML 조문 변경 2개, 동일 24개. 이는 별표를 포함한 전체 규정 변경 건수가 아니다.
- npm audit --omit=dev: 취약점 0개. 알려진 의존성 취약점 검사 결과이며 전체 보안 검증을 의미하지 않는다.
- git diff --check 통과. npm pack --dry-run: 신규 테스트 포함 18개 파일, 약 38 KB.

## 다음 개선 우선순위

1. **높음 — HWP 별표·첨부 개정 비교.** 현재 비교는 HTML 조문만 대상으로 한다. 표의 금액만 바뀐 경우를 다루는 HWP 비교와 누락·불완전성 표시가 필요하다. 표 구조 변경과 파서 출력 차이를 실제 개정 쌍으로 검증해야 한다.
2. **높음 — 기준일 적용 판단과 v0.7.0 통합 검토.** 별도 `agent/v0.7.0-p0-verify-applicable-aliases` 브랜치에는 인용 검증, 기준일 조회, 별칭 기능이 이미 있다. 해당 브랜치를 자동 병합하지 않았다. timeline.js는 개정일로 후보를 고르고 시행일 주의문을 제공한다. 실제 적용본 확정에는 부칙·경과조치·조문별 시행일 검토가 필요하다. 이 기능을 새로 중복 구현하기보다 기존 브랜치를 검증한 후 이번 수정과 통합하는 편이 적절하다.
3. **높음 — 본문·목차의 HISTORY_ID 소속 검증 확대.** 이번에는 개정 비교의 소속 검증을 추가했다. get_rule_content/get_rule_toc에서 유효한 정수지만 다른 규정에 속한 HISTORY_ID도 차단하도록 확대할 필요가 있다.
4. **중간 — 동시 요청 제한과 캐시 안정성.** fetchResponse의 500ms 대기는 병렬 호출이 같은 시각에 깨어날 수 있어 전체 요청 간격을 보장하지 않는다. 요청 큐, 동일 요청 공유, 원자적 캐시 쓰기를 도입하고 동시 요청·중단 테스트를 추가할 필요가 있다.
5. **중간 — 오류 원인 구분과 실사이트 검사 강화.** HTTP 503을 모두 IP 차단으로 단정하는 안내를 서비스 장애 가능성과 구분해야 한다. smoke-live.js는 일부 비정상 HTTP 응답에서도 성공 로그를 남기고 운영 파서 대신 별도 코드를 사용한다. 실사이트 검사도 실제 MCP 호출을 재사용하도록 정리하는 것이 좋다.
6. **중간 — 캠퍼스·런타임 지원 확인.** seoul=1/wise=2는 README상 추정값이다. 공식 화면의 실제 분류와 결과를 대조해야 한다. Node 18 이상 표기도 현재 잠금 의존성과 지원할 Node 버전별 CI로 검증해야 한다.

## 부분·미검증·보류

- 최신성은 연혁 캐시 최대 10분 및 사이트 연혁 정렬에 의존한다. 특정 기준일의 시행 규정 확정은 구현하지 않았다.
- v0.7.0의 전체 코드·회귀 테스트, 다른 모든 규정, 캠퍼스 코드, Notion 실제 연결, 운영 서버 버전은 미검증이다.
- 운영 재시작·배포, GitHub push/PR, npm 발행은 수행하지 않았다. 변경 내용은 로컬 개선 브랜치의 미커밋 파일이다.
