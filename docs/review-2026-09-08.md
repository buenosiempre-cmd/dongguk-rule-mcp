# v0.8.1 검토·개선

기준 커밋: `2434ccb` (v0.8.0). 실제 Codex 설정은 v0.6.0 태그를 사용했고, 로컬 HTTP 서비스는 v0.8.0을 실행 중이었다.

## 수정

| 문제 | 결과 | 변경 |
| --- | --- | --- |
| 전문검색이 검색 캐시의 HISTORY_ID를 사용 | 이전 개정본의 조문과 날짜 반환 | 연혁에서 최신 ID·날짜를 선택하고 해당 본문 조회 |
| 재무 근거 조회가 필수 사실 누락에도 진행 | 기준일 미입력 시 최신본, 캠퍼스 미입력 시 서울로 조회하고 `retrieved` 표시 | 누락 시 외부 조회 없이 `needs_input` 및 누락 목록 반환 |
| WISE 표기 변형을 서울로 처리 | `wise`, 공백 포함 WISE, 경주 입력의 잘못된 필터 | 캠퍼스 정규화, 알 수 없는 값 거부 |
| HWP 실패 뒤 빈 HTML도 조회 성공 처리 | 내용 없는 결과를 근거로 오인 | `CONTENT_UNAVAILABLE` 반환 |
| Node 18 지원 안내와 실제 의존성 요구 불일치 | Node 18 설치·실행 실패 가능 | 최소 Node 20.19, Node 20.19·22·24 CI 추가 |
| 설치 패키지에 의존성 잠금파일 미포함 | 설치 시점에 따라 검증되지 않은 전이 의존성 사용 | npm-shrinkwrap.json 패키지 포함 |
| 실사이트 스모크가 별도 파서·HTTP 상태 판단 사용 | 실제 MCP 고장에도 성공 표시 가능 | 캐시 없는 실제 stdio MCP 핸들러로 검증 |

## 검증 방법

- 새로운 회귀 사례로 수정 전 11개 실패를 재현했다. 수정 후에는 특수 캠퍼스 입력 2개를 추가해 16개 검증한다.
- 전체 오프라인 스위트는 13개, 검증 항목은 338개다. 재무 50개는 합성 지식팩 기반이며 법률 정답률 평가가 아니다.
- 실사이트 MCP 스모크: initialize 버전, 11개 도구, HWP 성공, 최신 연혁 일치, 본문·목차, 소속 없는 HISTORY_ID 거부, HTML 범위 개정 비교, 전문검색 최신성 등 9개 검사.
- npm audit --omit=dev: 알려진 취약점 0개. 전체 보안 감사 결과를 뜻하지 않는다.
- 배포 tarball을 별도 디렉터리에 풀어 npm ci와 전체 테스트로 설치 가능성을 검증한다.

## 남은 범위

- 별표·첨부 개정 비교는 아직 지원하지 않는다. 개정 비교는 HTML 조문 범위다.
- 캠퍼스 입력값 정규화와 실제 학교 LAWGROUP 코드·규정 적용 범위 확정은 별개다. 코드 값과 캠퍼스별 적용성은 미검증이다.
- 기준일 조회는 개정일 후보와 시행일 주의사항을 제공한다. 부칙·경과조치를 포함한 적용 규정 자동 확정은 지원하지 않는다.
- HTTP health는 프로세스 상태만 의미한다. 원문 접속은 실제 MCP 호출로 따로 검증해야 한다.
- 기존 v0.8.0 재무지식 팩 내용과 국가 법령 연결 전체는 이번 변경 검토 범위에 포함하지 않는다.
