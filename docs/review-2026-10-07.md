# v0.10.1–v0.10.3 오류 수정 및 성능 개선

## 후속 변경 v0.10.2 / v0.10.3

- v0.10.2: 구조화 결과를 숨기는 앱에서도 서비스 버전·프로필·도구 수, 원문 유형·발췌 상태·부분 조회 사유를 확인하도록 Markdown 응답에 표시한다. 관련 회귀 검사 6개를 추가했다.
- v0.10.3: `DONGGUK_MCP_WARM_RULES`로 선택한 공개 규정을 유휴 시간에 순차 조회한다. 캐시 수명의 80%부터 미리 갱신하되 기존 만료시간은 유지한다. 갱신 중에는 유효한 캐시만 즉시 반환하며, 만료된 캐시는 새 조회를 기다린다.
- 학교 로그인 쿠키를 제거한 rules 컨텍스트로만 사전 조회한다. 비공개 캐시 분리, 동일 키 조회 합치기, 사용자 요청 시 다음 사전 조회 연기, 실패 후 재시도 간격, 종료 시 타이머 해제를 검증했다.
- 전체 오프라인 테스트 23개 스위트 통과. 새 캐시·사전 준비 회귀 검사 29개 통과.
- 실제 원문 HTTP 비교 108회 성공, 규정별 발췌 해시 동일. 로컬 첫 조회 중앙값은 빈 캐시 1,671.6 ms에서 사전 준비 완료 후 5.8 ms로 감소했다. 사전 준비 약 6.18초와 원문 요청 11회/회차는 별도 비용이다. [방법과 한계](PERFORMANCE.md)

아래는 v0.10.1 당시의 수정·검증 기록이다.

기준: 2026-10-07, v0.10.0 (`2a1e561`). 기존 테스트와 대표 원문 조회가 통과하는 상태에서도 추가 재현 검사 14개 중 11개가 실패했다. 이번 변경 후 14개 모두 통과했다.

## 수정한 동작

| 문제 | 기존 동작 | 수정 결과 |
|---|---|---|
| 규정명과 자연어 질문을 동시에 입력 | `rule_keyword`가 있으면 `query`를 발췌 검색에서 제외하여 원문 앞부분만 반환 | 질문의 검색어로 관련 조문·별표를 찾고, 명시한 `terms`가 있으면 우선 사용 |
| 검색 서버가 HTTP 200으로 장애 화면을 반환 | 결과 0건으로 해석하고 캐시에 저장 | 검색 건수·결과 구조를 확인하고 `UPSTREAM_FORMAT_CHANGED` 반환. 정상 0건은 계속 `NOT_FOUND` |
| Finance Desk에 `별표 1의2` 요청 | `별표 1`로 잘라서 다른 별표를 요청 | 가지 번호를 보존하여 법령 어댑터로 전달 |
| 별표의 텍스트 응답 누락 | 구조화 응답에는 별표가 있으나 Markdown에는 조문 본문만 출력 | 별표 본문·선택 번호·조회상태·원문 링크·시점 미확인·잘림을 함께 출력 |
| 통합 규정 조회의 부분 상태 | 경고나 빈 발췌가 있어도 통합 상태 필드가 없음 | 응답/규정별 `evidenceStatus`와 규정별 `incompleteReasons` 추가 |

`retrieved`는 요청한 발췌의 확보 상태이며 규정의 적용성·표 해석·법적 적정성을 확정하지 않는다. `HWP_FALLBACK`, `NO_MATCHING_EXCERPT`, `EXCERPT_TRUNCATED`, `RULE_IDENTITY_UNCONFIRMED`는 `partial`로 표시한다.

비정상 검색 응답 방지는 새로 조회하는 응답에 적용된다. 이전 버전이 이미 저장한 검색 결과는 캐시 만료 전 남을 수 있다. 운영 적용 시 공개 검색 캐시를 보관 이동하여 새로 조회할 수 있다. 본문과 연혁 캐시는 이 변경으로 영향을 받지 않는다.

## 의존성

`npm audit --omit=dev` 기준으로 알려진 취약점이 있는 패키지 5개(critical 1, high 2, moderate 2)를 0개로 줄였다. 호환 범위 내 수정이며 `npm-shrinkwrap.json`으로 설치 버전을 고정한다.

| 패키지 | 이전 | 이후 |
|---|---|---|
| `@modelcontextprotocol/sdk` | 1.30.0 | 1.32.1 |
| `fast-uri` | 3.1.7 | 3.1.8 |
| `ip-address` | 10.3.1 | 10.7.3 |
| `proxy-addr` | 2.0.7 | 2.0.8 |
| `undici` | 7.29.0 | 7.30.0 |

경고 수는 이 서비스에서 실제 공격이 가능하다는 판정이 아니다. 예를 들어 [SDK의 OAuth 권고](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6qxp-vccf-f47h)는 SDK 서버 및 stdio 클라이언트를 영향 대상에서 제외한다. [proxy-addr 권고](https://github.com/advisories/GHSA-jqcg-44mw-7w3h) 역시 신뢰 프록시 사용 방식에 따라 영향을 판단해야 한다. 이번 업데이트는 의존성 위험을 줄이는 유지보수이며 전체 보안 감사는 아니다.

`npm run audit:deps`를 추가하고 기존 CI에 포함했다. `node-fetch` 3.x는 CommonJS 사용 방식의 변경이 필요한 주요 버전이므로 이번 수정에 포함하지 않았으며, 유지한 2.7.0에는 이번 audit의 경고가 없다.

## 검증

- 전체 오프라인 테스트: 22개 파일, 각 스위트 집계 합산 614개 검사 통과. 합성 데이터 검증이며 법률 정답률을 의미하지 않는다.
- 추가 회귀: 수정 전 3개 통과·11개 실패 → 수정 후 14개 통과·0개 실패.
- 실제 MCP 스모크: 캐시·로그인 쿠키 없이 9개 검사 통과.
- 분야별 원문: 학사·교원 인사·직원 근무·출장·회계·결재 권한·연구·학생 지원 8개 모두 HWP·연혁·HTML 본문 연결 확인. 후보의 업무 적용성을 확정한 검사가 아니다.
- 설치 진단: v0.10.1, 공개 `rules` 도구 10개 등록 확인.
- 의존성 audit: 알려진 취약점 0개.
- 패키지 점검: 내부 자료팩·운영 환경파일·토큰 등록부를 포함하지 않음.

## 배포 및 남은 범위

공개 설치 링크는 기존 v0.10.0 릴리스를 유지한다. 개선 브랜치의 병합·공개 태그·릴리스 게시 여부는 별도로 확인한다. 운영 설치는 검증한 패키지와 복구 가능한 이전 버전을 구분하고, 실제 서비스 버전·인증·원문 조회를 재확인해야 한다.

기관 SSO, 전 구성원 앱 연결, 모든 규정·법령·별표의 해석 정확성, 동시 이용 규모 및 업무시간 개선은 이번 검증 범위에 포함하지 않는다. 이미 연결된 stdio MCP 프로세스는 재연결 전까지 이전 버전을 유지할 수 있다.
