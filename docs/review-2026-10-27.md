# v0.10.4 업무 조회·연결 진단 개선

기준일: 2026-10-27. GitHub main은 v0.10.0(`2a1e561`), 기존 개선 PR #6은 v0.10.3(`f1233e8`), 공용 서버의 `/health` 응답은 v0.10.3이었다. 이 변경은 기존 개선 브랜치 위에 추가했다. 기본 브랜치 병합과 공용 서버 교체는 별도 작업이다.

## 확인하고 수정한 문제

| 문제 | 재현 | 수정 |
|---|---|---|
| 자연어 규정명 누락 | `취업규칙 제62조 임금 지급일`에서 전체 문장을 규정명으로 검색 | 규칙·세칙·학칙·정관·지침·내규 등의 명칭 인식 |
| 따옴표 안 규정명의 공백 손실 | `「연구비 관리규정」`을 `관리규정`으로 축소 | 따옴표 안 전체 명칭 보존; 복수 규정은 첫 규정을 임의 선택하지 않음 |
| 발췌 구간 수 제한이 숨겨짐 | 관련 6개 블록 중 4개만 반환하면서 `truncated:false` | 생략 개수·블록/문자 제한 분리, `partial` 및 `EXCERPT_BLOCK_LIMIT`, 읽기용 응답에도 생략 표시 |
| 진단의 과도한 성공 표시 | 도구의 `ok:true`만으로 HTML 대체·빈 발췌도 원문 진단 통과 | 규정/개정본 식별자·비어 있지 않은 HWP 발췌·확인 상태 검사; 의도한 표본 잘림은 공개하고 허용 |
| 의존성 권고 추가 | v0.10.3 고정 의존성에서 영향 패키지 6개(high 3, moderate 3) | 호환 범위 갱신 후 `npm audit --omit=dev` 0개 |

`retrieved`는 요청 발췌 확보를 뜻한다. 금액·전결권자·시행일·캠퍼스별 적용 적합성의 최종 판정이 아니다. 블록 생략이 표시되면 검색어를 좁히거나 한도를 늘려 필요한 조문·예외·별표를 보완한다.

## 검증

- Node 24.19.0에서 전체 오프라인 테스트 25개 스위트 통과. 새 업무 조회 검사 13개와 진단 검사 10개 포함.
- 캐시·로그인 쿠키를 끈 실제 MCP에서 취업규칙·교원인사규정·여비규정·위임전결규정 4개 모두 HWP 조회 성공.
- 취업규칙 자연어 질문에서 제62조가 포함된 발췌를 확보했다. 취업규칙과 여비규정의 제한된 발췌는 `partial`로 표시했다.
- 실제 HWP 원문 진단: 공개 도구 10개, 여비규정 LAW_ID 184 / HISTORY_ID 3350. 의도한 표본 잘림을 표시하면서 통과.
- 기존 프로토콜·HTTP·캐시·시점·별표·인용·Finance Desk 회귀검사 유지.

실제 원문 검사는 조회 경로 확인이며 법률/규정 해석 정답률 측정이 아니다. 기관 SSO, 동시 이용 규모, 공용 서버의 이번 버전 교체는 이 소스 검증 범위가 아니다.

## 바로 적용할 업무 활용

[업무 활용 가이드](WORKFLOWS.md)에 급여·수당, 출장비·별표, 위임전결, 과거 기준일 감사, 기안문 인용 검증의 질문 예시와 도구 입력을 정리했다. 단일 규정 조회는 `lookup_dongguk_rule`, 과거 시점은 `applicable_rule`, 기안문 인용은 `verify_rule_citations`로 시작한다.

후속 개선 우선순위는 다음과 같다.

1. **배포 일치:** PR 병합·릴리스와 공용 서버·각 앱의 실제 버전을 함께 관리한다. 설치 안내의 공개 릴리스 링크는 실제 게시된 v0.10.0을 유지했다.
2. **업무별 평가 자료:** 자주 받는 비식별 질문과 담당자가 확인한 근거를 모아 검색 성공률·조문 누락·수정시간을 측정한다. 합성 회귀검사만으로 업무 정확도를 주장하지 않는다.
3. **개정 영향 확인:** 급여·여비·전결 규정의 개정본 ID 변경을 감지해 연결된 매뉴얼을 검토 대상으로 표시하는 흐름을 추가할 수 있다. 이번 작업에서는 정기 실행을 등록하지 않았다.
4. **별표 품질:** 병합 셀·단위·주석을 원문 위치와 연결하고, 표 구조를 확인할 수 없는 경우 담당자가 원문을 볼 수 있게 한다.
5. **내부 Desk 연계:** 공개 rules와 별도로 검토된 재무 온톨로지·해설서·실무 자료팩을 finance 프로필에 연결한다. 공개 규정 조회만으로 내부 매뉴얼 검토가 완료된 것은 아니다.
