# 벡터 세대 보존·정리

PR #53의 실제 디스크 구조를 유지한다. 벡터는 `semantic-v1.<SHA-256>.bin`, `semantic-v1.json`이 현재 벡터를 가리키는 포인터다. 세대 폴더로 바꾸지 않으며, 어떤 폴더도 재귀 삭제하지 않는다.

## 정리 규칙

벡터를 먼저 저장하고 정보 파일을 rename으로 게시한 뒤 정리한다. CLI 빌더와 HTTP 자동 갱신은 같은 `saveSemanticIndex` 경로를 쓰므로 둘 다 적용된다. 현재와 직전의 **서로 다른 성공 세대**는 항상 남긴다. 같은 내용 재게시는 직전을 바꾸지 않는다. 그보다 오래된 세대는 **현재에서 내려온 시각부터 1시간**이 지난 다음 게시 때 삭제한다. 변경이 잦으면 유예 중인 여러 세대가 잠시 더 남을 수 있다. 파일 수정 시각이 오래됐다는 이유만으로 방금 퇴역한 세대를 삭제하지 않는다.

새 빌더가 직접 저장한 벡터만 포인터의 `retention`에 생성 기록을 남긴다. 삭제에는 아래 조건을 모두 요구한다.

- producer·형식 버전·파일명·SHA-256·바이트·dev/ino·퇴역 시각의 생성 기록이 유효하다.
- 이름이 정확히 `semantic-v1.<64자리 소문자 SHA-256>.bin`이고 현재·직전 세대가 아니다.
- regular file이며 symlink·hardlink가 아니고, 생성 당시 dev/ino·크기와 같다.
- 실제 바이트의 SHA-256이 생성 기록과 같다. 검증 후 포인터와 파일 identity도 재확인한다.
- semantic 디렉터리가 symlink가 아니며 동일 게시 잠금을 보유하고 있다.

이름만 맞는 사용자 파일, 세대처럼 생긴 디렉터리, 모델 폴더, 예전 `semantic-v1.bin`, 생성 기록이 없는 기존 해시 파일은 자동삭제하지 않는다. 게시 전에 프로세스가 종료돼 남은 벡터도 포인터에 생성 기록이 없으면 미추적으로 보존한다. **따라서 기존 미추적 세대까지 소급해 두 개로 줄이지 않는다.** `/status`의 미추적 수·용량으로 별도 검토할 수 있다. 손상된 optional 생성 기록은 정리만 중단하고 정상 벡터 로딩은 막지 않는다.

## 동시 실행·실패 처리

게시와 정리는 `.semantic-publish.lock`의 `wx` 잠금으로 직렬화한다. 살아 있는 프로세스·EPERM·손상 잠금은 임의로 해제하지 않는다. 기록된 PID가 ESRCH로 확인된 경우에만 해당 무작위 토큰의 회수 claim을 `wx`로 취득하고, 기존 잠금의 토큰·dev/ino·PID 사망을 다시 확인한 뒤 회수한다. 같은 stale token을 본 두 회수자가 새 writer의 잠금을 지우지 않도록 claim이 한 회수자만 허용한다. 회수 중 프로세스가 죽어 남은 claim이나 JSON 작성 전 죽어 손상된 잠금은 자동회수하지 않으며 관리자 확인이 필요하다.

모든 동시 저장자가 이 잠금 프로토콜을 쓰는 버전이어야 한다. 배포 때 구버전 빌더/자동 갱신 프로세스를 함께 교체해야 한다. 구버전 writer나 외부 프로그램이 정리 도중 파일을 임의로 교체하는 경쟁까지 원자적으로 보호하는 기능은 아니다. 포인터 rename은 프로세스 중단에 대한 게시 원자성이며 전원 장애 뒤 fsync 영속성 보장은 범위 밖이다.

게시 후 삭제가 실패해도 새 색인은 성공으로 유지하고 정리 결과에 오류 코드를 남긴다. 오래 멈춰 유예시간을 넘긴 reader가 이미 정리된 벡터를 만나면 최신 포인터를 한 번 다시 읽고, 여전히 실패하면 기존처럼 낱말 검색으로 폴백한다. 라이브러리의 `cleanupSemanticGenerations(directory)`도 같은 잠금·소유권 규칙을 쓰며 삭제 대상을 지정하는 우회 옵션은 제공하지 않는다.

## `/status` 필드

기존 관리자 인증을 거쳐 `semanticSearch.storage`에서 읽는다. GET/HEAD는 잠금 생성·회수·파일 정리·포인터 갱신을 하지 않는다.

| 필드 | 뜻 |
|---|---|
| `generationCount`, `totalBytes` | 세대 이름 형식에 맞는 단일 링크 regular file 수·바이트. 미추적 포함 |
| `managedGenerations`, `managedBytes` | 생성 기록의 identity·크기와 일치하는 파일 수·바이트 |
| `protectedGenerations` | 현재 또는 직전으로 보호한 파일 수(미추적도 보호될 수 있음) |
| `graceGenerations` | 생성 기록은 있으나 퇴역 후 1시간이 지나지 않은 비보호 세대 |
| `graceExpiredCandidates` | 유예가 지난 비보호 후보. 상태 조회는 내용 해시를 읽지 않으므로 실제 삭제 가능 수와 다를 수 있음 |
| `candidateHashesVerified` | 항상 false. 실제 삭제 직전에만 SHA-256을 확인 |
| `untrackedGenerations`, `untrackedBytes` | 소유를 확인할 수 없어 자동삭제하지 않는 파일 수·바이트 |
| `ignoredEntries` | 세대 이름을 가졌지만 링크·폴더 등이라 제외된 항목 |
| `publicationLocked` | 현재 게시 잠금 경로 존재 여부. PID 생존을 뜻하지 않음 |
| `lastCleanup`, `lastCleanupScope` | 현재 프로세스의 최근 정리 시각·삭제 수/바이트·보류 수·오류 코드. scope는 process. 재시작/다른 빌더 프로세스의 결과는 null이며 영속 기록이 아님 |
| `trackingAvailable`, `graceMs`, `code` | 유효한 생성 기록 여부, 유예시간, 디렉터리 없음/안전하지 않음 등 상태 코드 |

파일 경로나 예외 원문은 상태에 노출하지 않는다. 마지막 정리 결과와 달리 세대 수·용량은 매 상태 조회에서 실제 디스크를 확인한다. SHA-256 재확인은 삭제 후보에만 수행하므로 상태 조회 때마다 전체 벡터를 해시하지 않는다.

## 검증

`node test/test-semantic-generations.js`는 새 임시 디렉터리만 사용한다. 현재·직전/유예·동일 세대/재등장·미추적·사용자 자료·폴더·symlink/hardlink·손상·중간 파일교체·삭제실패·동시 회수자·오래 멈춘 reader·실제 HTTP 인증 및 읽기 전용 상태를 검사한다. 기존 `test/test-semantic.js`의 네 게시 실패 지점과 프로세스 종료 검사도 유지한다. 실제 공유 캐시·사용자 자료·실모델은 정리 검증에 사용하지 않는다.
