# 설계·레드팀 지시 반영 및 신규 오답 대사 (2026-11-27)

> **D1 수정 전 기준 — 채택 판단 보류.** 이 보고의 수치·계수는 본문 누락 결함이 있는 corpus(SHA-256 `47118b4a…`)로 측정했다. 레드팀은 본문 없는 제목만의 조문 1,656개(약17%), 관련 규정248개를 보고했다. t10x의 파서 수정·색인 재생성 및 기준선 재측정 이후 JEV도 재학습·교차검증해야 한다. 현재 수치를 수정 후 성능으로 인용하지 않는다.

**기존 실험은 검색 후보·조문 선택 실험이다. 실제 MCP 발췌 본문의 엄격 정답률과 legacy 대비 성적은 미측정이다.** 다음 표는 기존 공개 결과를 다시 집계한 것으로 재학습·계수 조정은 하지 않았다.

## 작업 경계와 데이터

- `src/corpus.js`·`src/index.js` 순위 코드와 `src/fusion.js`는 수정하지 않는다. t110의 `rankRules` 훅 확정 후 계약에 맞춰 새 JEV 모듈 경계로만 연결한다.
- 학습·조정은 저장소 공개 train46/dev25 및 이후 명시적으로 추가하는 새 개발 문항만 허용한다. 현재 수집기는 두 fixture만 허용하며 v4~v6·v7~v10·질문 DB를 사용하지 않았다.
- 현 실험은 전체 질문 외 텍스트 키도 dense 인코딩한다. 설계의 질문당1회(핵심어 포함2회) 통합 예산을 충족한 결과가 아니다. 통합용은 추가키 dense 인코딩을 제거한 특징 계약과 별도 고정 설정으로 재학습·재측정해야 한다. 기존 모델 계수와 성적을 그대로 재사용하지 않는다.
- 규정 확률은 최고 조문 확률의 단변량 보정이며 설계가 권고한 log 조문 수/상위2평균/범위 등 다변량 2단 모델은 미구현이다. max 집계는 증거 수를 더하지 않지만 큰 규정의 최댓값 기회 편향을 완전히 제거하지는 않는다.
- 문항을 임의 분할하는 대신 정답 규정 그룹 5-fold를 사용했다. 기존 train→dev는 별도 평가했으나 역방향 leave-one-set-out·주변 하이퍼파라미터 민감도 검증은 미실시다. 현재 결과를 설계의 최종 채택 기준 통과로 표시하지 않는다.

## D1 영향과 재측정 조건

- 근거는 레드팀 `레드팀_의미기반검색확장_20261127.md`의 D1 및 PR55 검수 기록이다. 본 페인은 파서 원인을 독립 확정하지 않았고 그래프 실측을 반복하지 않았다. 제목만 조문1,656개/규정248개는 레드팀 보고값이다.
- 기존 보고의 83.1%→90.1%, 규정top3 63→66/71, 지연13.52/28.27ms, 계수/보정오차 모두 **D1 수정 전 조건**의 기록이다. 기존 조문 적중은 조문 식별자 라벨 기준이므로 본문 보유나 실제 발췌 정답을 보장하지 않는다.
- 증거 원본과 점수·분할·계수는 역사적 결과로 보존한다. `results/report.json`에는 dataQuality 메타데이터만 추가했고 `results/data-quality.json`에도 동일 상태를 기록했다.
- 레드팀이 제시한 문항단위 정확 McNemar(부호) 검정은 개선5·악화0에서 양측 p=0.0625로 5% 기준 유의하지 않다. 기존24그룹 부트스트랩 구간을 개선 확정 근거로 사용하지 않는다.
- t10x의 파서 수정·색인 재생성·공개 기준선이 준비되면 새 corpus/벡터 해시와 누락 감소 대사를 확인하고, 동일 새색인에서 기본 RRF와 JEV를 다시 측정한다. D1 수정 전후 수치와 순위 방식의 차이를 한 효과로 합치지 않는다.
- 기존 모델 지문에 corpusHash가 포함되어 새 색인에서 기존 계수가 거부되어야 한다. 이를 확인한 뒤 저장소train/dev만으로 재학습/교차검증한다. 보류셋 요청·v4~v6 사용은 하지 않는다.
- `corpus.js`·`index.js` 순위 및 `fusion.js`는 t110 소유, 파서와 색인 복구는 t10x 소유로 유지한다. 이 페인은 해당 코드와 캐시를 수정하지 않았다.

## 그래프 통합 방향 제약

- 가점 허용은 **상위 규정 seed → 명시적으로 확인된 하위 시행세칙·내규** 방향뿐이다. 간선 저장 방향이 implements(하위→상위)라면 조회 방향을 반대로 해석해야 하므로 t110 훅에서 의미상 하향을 확인한다.
- 상향(작은 규정→큰 규정), 일반 인용, 방향 불명 관계는 후보 수가 많다는 이유로 가점하지 않는다. 관계명이나 이름 길이만으로 상하위를 추정하지 않는다.
- 같은 D1 수정 후 색인과 고정 설정에서 그래프 없음 / 하향만 가점의 효과를 별도로 비교한다. 상향·방향 불명은 가점0을 검증하고 해당 방향이 후보/특징으로 유입됐는지 별도 집계한다. 규정top3·엄격본문·조건부발췌 포함·새오답·큰 규정 유입을 나눠 보고한다.
- 레드팀의 기존 그래프 생성131ms·seed329/513(64%) 빈 결과는 D1 수정 전 참고값으로 인용한다. 같은 색인의 생성/빈결과 측정은 반복하지 않으며 데이터 수정 후 필요한 효과 비교만 한다. 현재 JEV 실험에는 그래프가 연결되지 않았다.

## PR55 재검수 후속 — 라이선스·산출물 보존·재평가

- `src/jev.js`의 라이선스 주석을 실제 npm 패키지에 포함되는 `docs/JEV-LICENSE`로 수정했다. 원본 저작권 고지 내용은 변경하지 않았다.
- **병합 전 제거 필요:** `experiments/jev/results/report.json`과 `experiments/jev/results/evidence.json.gz`는 main 반영 전에 별도 보관 위치·해시를 확보하고 저장소 추적 대상에서 제외해야 한다. 지금은 대표 지시대로 두 파일을 삭제하거나 수정하지 않는다. 기존 커밋 이력을 재작성하지 않는다.
- 라이선스 주석도 `jev.js` 전체 소스 지문의 일부이므로 현재 지문은 기존 D1 실험 모델과 달라진다. 기존 지문·계수를 새 값으로 덮어써 통과시키지 않고 역사적 증거로 보존한다. 필요한 과거 재현은 결과가 기록한 구현 커밋에서 수행한다.
- 코디네이터가 t10x의 D1 수정 corpus 경로를 전달하면 새 색인·벡터 정합과 지문을 먼저 확인하고 재학습·그룹 교차검증한다. 현재는 경로 전달 전이며 결함 색인으로 다시 학습하지 않는다.
- 재평가의 우선 비교 기준은 t110 공통 하네스의 실제 생산 `searchCorpus`/`legacy`이다. 연결이 가능하면 동일 수정 corpus·동일 질문·동일 발췌 조건에서 생산 기준선과 JEV를 비교한다. 연결 전 실험 BM25/RRF 결과는 별도로 표시하며 생산 기준선이라고 부르지 않는다.
