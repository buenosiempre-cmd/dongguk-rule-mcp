# 동국 규정·한국법령 공동 검토

등록된 `dongguk-rule`과 `korean-law` MCP를 사용한다. 도구 이름은 현재 도구 목록에서 확인한다. 이 스킬은 근거 조회·대조용이며 지급·신고·결재·외부 전송 권한을 추가하지 않는다.

## 질문에 맞는 조회 선택

- **교내 규정 하나의 내용·조문·지급일·전결권한:** 동국규정 `lookup_dongguk_rule`부터 사용한다. 이미 확인한 LAW_ID의 특정 조문은 `get_rule_content`. 법령 쟁점이 없는 질문에 국가 법령 조회를 덧붙이지 않는다.
- **출장비·외부 강사료의 규정과 세무 기준 검토:** `review_finance_case`가 제공되면 우선 사용한다. 이 도구는 확인한 사실에 따라 관련 규정과 한국법령을 함께 조회한다. `get_finance_evidence`는 별도 내부 자료팩이 필요한 기능이므로 자료팩 미설정을 우회하려고 임의의 팩을 만들지 않는다.
- **지원 범위 밖 급여·연금·비거주자·국외 강연·산학협력단·병원 업무:** 자동 분류 결과가 `scope_review_required` 또는 `specialist_review_required`이면 그 상태를 설명하고 직접 조회로 전환한다. 적용 직군·제도·회계·거래 유형을 확인하고 규정 후보와 법령을 따로 찾는다. 일반 회계 특례규칙이나 공무원 기준을 대신 적용하지 않는다.
- **기안문 인용 검증:** 교내 규정은 `verify_rule_citations`, 국가 법령은 한국법령 `legal_analysis(mode="verify_citations")`. 필요한 비식별 인용 문장만 전달한다.

## 통합 조회에 전달할 사실

`facts`에는 대화·문서에서 확인된 조건만 넣는다. 거래일을 오늘로 바꾸거나 사람 이름·계좌·개인번호를 전달하지 않는다. 이미 알려준 사실은 다시 묻지 않는다.

공통 필수 사실: `base_date`(실제 업무 기준일), `campus`(서울/WISE), `accounting_unit`(교비회계 등).

- 출장비: `employee_role`(직원/교원 등), `travel_scope`(국내/국외).
- 외부 강사료: `employment_relationship`(있음/없음), `tax_residency`(거주자/비거주자), `service_pattern`(일시적/계속·반복), `service_location`(국내/국외). `internal_rule_name`은 실제 확인한 교내 지급 기준 명칭이 있을 때만 입력한다.

`needs_input`이면 반환된 질문을 이용해 중요한 조건부터 확인한다. 단순한 현행 조문 열람은 거래 사실을 요구하는 통합 도구 대신 개별 조회 도구를 사용한다. 출장비와 강사료가 섞인 질문은 항목별로 나누되 이미 확보한 조건·근거를 재사용한다.

## 개별 한국법령 조회와 시점

- 법령명이 확인되면 `search_law`로 식별자를 얻고 `get_law_text`로 필요한 조문을 읽는다. 법령명·조문 번호를 추측해 확정 근거로 사용하지 않는다.
- 과거 업무는 한국법령 `legal_analysis(mode="applicable_law", lawName, date)`로 당시 버전을 확인한다. 동국규정은 `applicable_rule`을 사용하되 개정일과 시행일·경과조치를 구분한다.
- 과거 별표는 한국법령 도구 스키마가 지원하는 `get_annexes(date=기준일)`을 사용하고 반환된 시점·버전을 확인한다. 조회 실패나 미확인 별표를 현행 별표로 대체해 과거 근거라고 하지 않는다.
- 통합 조회가 필요한 원문을 이미 확보했으면 같은 검색을 반복하지 않는다. 누락된 조문·별표·조건만 보완한다.

## 답변에 보존할 사항

법령 근거, 교내 규정, 함께 적용할 조건, 확인이 필요한 사항을 구분한다. 규정명·LAW_ID/HISTORY_ID, 법령명·MST·시행일, 조문/별표 위치와 원문 링크를 남긴다.

`partial`, `source_gaps`, 잘림, HTML 대체, 미확인 시점, 한쪽 MCP 장애를 결론에서 숨기지 않는다. 위임전결규정은 강사료 단가의 근거가 아니며, 강사료라는 명칭이나 일시 지급만으로 기타소득을 확정하지 않는다. 양쪽 문구가 다르다는 이유만으로 규정이 위법하다고 단정하지 않는다.

두 MCP 중 하나가 현재 도구 목록에 없으면 자동 연계가 완료됐다고 말하지 않는다. 제공되는 MCP로 가능한 근거를 확보하고 부족한 연결을 명시한다. 설정 변경·재설치는 사용자 요청 범위에서만 진행한다.
